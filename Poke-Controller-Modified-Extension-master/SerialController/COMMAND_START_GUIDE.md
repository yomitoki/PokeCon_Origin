# CommandsのStep実行設定

Stepを搭載したCommandsでStartを押すと、そのCommandsが公開した開始場所・終了場所をPokeConのポップアップに表示します。Commandsタブへの常設設定や独立した開始Step設定ではありません。Stepデバッグの停止地点・一時置換とは別の設定です。

## 設定手順

1. CommandsタブでStep対応Commandsを選び、Startを押します。
2. 表示されたポップアップで開始場所と、必要なら終了場所を選びます。
3. 候補が多い場合は、文字検索または状態グループで絞り込みます。
4. 同じ画面でデバッグ項目、セーブ削除ユーザー番号、失敗時再実行を指定します。
5. 「この設定で開始」を押します。

「Commands既定で開始」を押すと、保存した実行範囲だけを解除してCommands本来の開始位置で開始します。ポップアップを閉じた場合はCommandsを開始しません。

## お気に入り

現在選択している開始・終了・詳細設定は、Commandsごとに最大10件まで登録できます。

- 「新規登録」: 名前を付けて現在の設定を追加します。
- 「呼出」: 選択したお気に入りを現在の実行設定へ反映します。
- 「上書き変更」: 選択したお気に入りを現在の設定で更新します。
- 「削除」: 選択したお気に入りだけを削除します。

お気に入りと現在の実行設定はInputSetごとに保存されます。

開始・終了候補は次の形式から自動検出されます。

- ZA_Storyなどの`STATE_*_FUNCTION`
- DevStudio生成StepやStepサンプルの`STEP_LABELS`／`STEP_KEYS`
- FRLG形式の`cb_restart_flag`（番号と「開始～終了」の説明）
- Commandsが明示した`COMMAND_RUN_LOCATIONS`

終了場所は、その場所の処理を完了して次へ遷移した時点で停止します。FRLG形式ではCommands本来のストップ番号へ設定します。

ZA_Storyでは、選んだStepだけでなく、外側の `main_current_state_init` も自動設定します。Pythonソースは変更しません。
Start後は、Commandsタブの同じ行が `現在Step` 表示に切り替わります。ここに選択したStepが出ていれば、initは反映済みです。次のStep名に変われば、選択Stepの処理は完了しています。

### ZA_storyのResetDebug

`ResetDebug（リセット復帰確認）`をONにすると、照合済みの復帰経路ごとに初回だけ入力を止めて20秒待ち、登録した処理を実行します。処理はStepジャンプだけ、時刻変更後のジャンプ、ゲーム再起動後のジャンプを区別します。移動前の安全なStepから確認を開始する経路もあり、その入口と後続のComment判定は同じ完了履歴を共有します。再訪時は強制処理を行わず通常判定へ戻り、以後の実際の失敗に対する通常復帰は引き続き有効です。

初戦前のレポート後に対応する`1_STORY_FARST_POKEMON_SELECT`も確認対象です。初回は通常の会話・戦闘入力より先に20秒待機してゲームを再起動し、同Stepへ戻って通常進行します。初戦前には手持ちUIがないため、この地点へのリセット時だけは同Stepで使用する`POKEMON_ZA_CHAT_MARKER`（話しかける）もロード後の復帰確認に使います。`1_STORY_FARST_BATTLE`を直接開始した場合も、再起動後は`1_STORY_FARST_POKEMON_SELECT`へ戻ります。この2Stepは確認済み履歴を共有するため、SELECTからBATTLEへ進んでも二度目の強制リセットは行いません。履歴はCommands再実行時に初期化します。画面右上の「レポート中」を自動検出する機能ではなく、明示登録した地点を確認する処理です。ソース内の`AUTO_SAVE_POINT`コメントだけでは確認対象になりません。

このON/OFFはほかのデバッグ項目と同様にInputSetの現在の実行設定とお気に入りへ保存されます。`Commands既定で開始`ではOFFへ戻ります。20秒待機・前処理・再訪結果は`[RESET_DEBUG]`ログに残ります。時刻変更の前処理が180秒以内に完了しない場合は、途中状態のまま無期限に待たず、保持入力とCommon状態を解除して`EVENT_ENTRY_RECOVERY_PRE_ACTION_FAILED`で明示停止します。復帰先未決定の項目や、自分自身へ戻るだけの未対応項目をResetDebugが推測してリセットすることはありません。

ゲーム再起動を含む中継Stepは、実際の再起動成功後にだけ確認完了とします。中継先で20秒を重ねて待たず、必要な再起動も省略しません。再起動後はメニュー・技変更・BOX等の途中状態を初期化して、セーブ後に未保存だった処理を再実行します。INFIの復元確認は初回のDebugだけに限定し、長時間の正常な周回へ一般の停滞タイマーを適用しません。戦闘やメニュー処理を飛ばす通常進行用のCommentスキップは、強制確認の対象にしません。

今回照合した経路の会話送りには600秒の上限を設け、内部処理の待ち続けで外側の復帰判定が動かなくなる経路を解消しています。会話やHELPに一度も入っていないFIELDだけで会話完了になっていた一部Stepは、会話への突入も確認します。この指定は対象Stepに限定し、汎用helperの既定動作は維持しています。復元後は技の探索対象・探索回数・探索開始時刻も初期化します。

動画照合の実施範囲と残作業は`ZA_STORY_VIDEO_COVERAGE_20261017.json`へ記録しています。2026-10-18の再開で、前回未取得16本のうち15本を取得しました。全39本中38本について全区間を2fpsで抽出し、候補の代表画像を確認済みです。残る`0BUiKDrO_1s`（約67秒）は公開動画が利用できず、後日の依頼で再開します。自動の再取得予約は行っていません。

取得済み38本で確認した全487 Step・1,482件のセーブ表示証拠について、保存前後を分けて安全な復帰先と処理を確定し、実登録との照合を完了しました。これらは独立したセーブ確定回数ではありません。根拠と専用テストは`ZA_STORY_RESET_AUDIT_20261018/save_origin_completion/audit_index.json`を参照してください。未取得1本、全候補区間の連続画像の精査、2fpsより短い表示の完全回収、各地点の実機リセット確認は残っています。全体テストと実機確認はユーザー指定で後日実施とし、別のPokeConは起動していません。

ResetDebugは実機検証用です。ゲーム画面を対象Stepの直前状態に合わせ、録画と操作履歴を有効にしたうえで使用してください。成功判定では、初回20秒待機、前処理、指定Stepへの復帰、2回目の通常Comment判定、不要な再リセットがないことを一連で確認します。

### ZA_storyのBATTLE_DEBUG

`BATTLE_DEBUG（敗戦復帰を各戦闘で1回確認）`をONにすると、調査対象のFARST・TOWER・W・ABSOL・GURI戦を、Commands 1実行につき各1回だけ意図的に敗戦させます。現在の対象Stepは`1_STORY_FARST_BATTLE`、`2_STORY_TOWER_72`、`2_STORY_W_LANK_MOVE12`、`2_STORY_ABSOL_MOVE18`、`7_STORY_GURI_115`です。強制敗戦の確認中はZLと視点保持を解除し、HELP・選択肢・Xメニュー・Comment送りは通常どおり処理します。攻撃入力だけLへ置き換え、`POKEMON_ZA_FIELD_W`では次のポケモンを出す上入力を送ります。会話と戦闘Lv表示が重なっても、ZLを解除してから会話入力を送ります。

再戦しない`1_STORY_THIRD_BATTLE`、`2_STORY_ABSOL_MOVE7`、`8_STORY_STORY_LAST_6`は対象外です。`2_STORY_ABSOL_MOVE12`もライバル同席で意図的な敗戦が難しいため、候補設定をソース上でコメントアウトして無効にしています。

`POKEMON_ZA_LOSE`を確認すると`[BATTLE_DEBUG] ... DEFEAT_CHECK`を記録し、Bで敗戦画面を進めた後はその戦闘の通常処理へ戻ります。同じ戦闘を再試行しても再度の強制敗戦は行わず、別の対象戦闘では改めて1回だけ強制敗戦します。この実行履歴はゲーム内リセットでは消えず、Commandsを終了して再実行すると消えます。

`TOWER_72`では「目の前がまっくらになった！」も敗戦表示として確認します。敗戦後は`TOWER_71`の会話・再戦入口へ戻り、再戦は通常攻撃へ進みます。勝利を確認した後だけ`TOWER_73`から`TOWER_74`へ進みます。通常フィールドにも残るLv.表示だけでは攻撃せず、フィールド復帰を3秒継続して確認します。

赤い目が表示される対ポケモン戦用には、赤い目を優先し、5秒連続で消え、フィールドも確認できた場合に戦闘終了とする共通判定を用意しています。現在は`TOWER_36／37`で共有し、瞬間的な消失や暗転では移動へ進みません。マップ移動を開始した後は、その移動処理を継続します。

初戦はライバル固有の回復セリフで判定しません。専用LOSE・再挑戦選択肢、または戦闘を確認した後に勝利報酬なしの白Commentを経て固定の「勝負をしかけてきた！」が再表示された場合に敗戦を確定します。最初の戦闘開始表示だけでは敗戦にしません。`1_STORY_FARST_BATTLE_LOSE`で会話を送り、実際のFIELDを確認してから`1_STORY_FARST_BATTLE`へ戻します。通常FIELD表示のない初戦の直接再戦では、「狙う／技を指示」の操作HUDと戦闘Lv表示がそろい、会話・HELP・Xメニューが消えたことを復帰条件にします。初戦の勝利後Stepへはコイン報酬を確認した場合だけ進みます。

このON/OFFはInputSetの現在の実行設定とお気に入りへ保存され、`Commands既定で開始`ではOFFへ戻ります。実機調査用のため、録画と操作履歴を有効にし、ZL解除・通常の会話／選択肢入力・攻撃のL置換、および各対象戦の`START → L_ONLY／FIELD_W_UP → DEFEAT_CHECK → 通常再戦`を確認してください。白Commentだけでは勝敗を決めず、通常の会話入力を続けて専用の結果表示を待ちます。

## 変更しない場合

Start後のポップアップには次の3つの操作があります。

- 「この設定で開始」: 画面で選んだ開始・終了・デバッグ設定を反映します。
- 「Commands既定で開始」: 実行範囲設定を解除し、Commands本来のinitで開始します。
- 「キャンセル」: Commandsを開始しません。

設定自体が不要になった場合はStart後のポップアップで「Commands既定で開始」を押します。対象Commandsの実行範囲がInputSetからも削除されます。お気に入りは個別に削除するまで残ります。

## 注意

- Stepを変更しても、ゲーム内の座標、会話、所持品、進行フラグは変更されません。
- ゲーム画面を選択Stepの開始状態に合わせてからStartしてください。
- Step名は必ずしも移動処理を表しません。画像が一致するまで待つStepや、会話を送るStepでは、スティックが動かず停止しているように見えることがあります。
- 例: `1_STORY_OUT_HOTEL_Z_73` は会話・画面条件の処理です。フィールド上の移動処理を再開したい場合は、ゲーム状態を確認したうえで次の `1_STORY_OUT_HOTEL_Z_74` を選びます。
- 「Start時にゲーム画面の状態確認を表示する」をONにしておくことを推奨します。
- 既存の `*_current_state_init` があるCommandsではinitへ設定します。initがないCommandsでは、生成したCommandsインスタンスの現在Stepだけを変更します。

## Commands側で説明・デバッグ・セーブ削除を登録する

自動検出だけで不足する場合はCommandsクラスに次を定義できます。

```python
COMMAND_RUN_LOCATIONS = [
    {
        "id": "chapter_1",
        "label": "第1章",
        "description": "自室から最初の町まで",
        "mode": "state",
        "variable": "STATE_MAIN_FUNCTION",
        "value": "MAIN_CHAPTER_1",
    },
]

# この宣言があるCommandsだけ、Start後にStep実行ポップアップを表示します。
COMMAND_RUN_SETTINGS = True

COMMAND_DEBUG_OPTIONS = [
    {"attribute": "DEBUG", "label": "画像保存デバッグ", "default": False},
]

COMMAND_SAVE_RECOVERY = {
    "method": "delete_save_for_user",
    "user_attribute": "save_delete_user_number",
    "max_retries": 1,
}

def delete_save_for_user(self, user_number):
    # ゲーム／機種に合った安全なセーブ削除操作を実装する
    ...
```

セーブ削除はゲームや機種で操作が異なるため、PokeCon共通処理が推測して削除することはありません。明示した削除関数がないCommandsでは失敗再実行を選択できません。削除関数で例外が発生した場合も再実行せず停止します。

## 1280×720表示で下のタブが見切れる場合

MainPanel上の「MainPanel操作をクイック側へ移動」をONにすると、上部の操作ボタンを右側クイックアクションへ移し、映像の上の1行を省けます。「＋ クイック設定…」からも切り替えられます。OFFにすると元の配置へ戻ります。

- 移動先のStart／Capture等は元の操作と同じです。移動モードを切り替えるだけではCommandsやゲーム入力を実行しません。
- 映像の表示サイズを保ち、右側ログの高さだけを調整します。既存のクイック項目・左右配置・ログ比率は維持します。
- このモードはInputSetごとに保存され、同設定再起動でも引き継ぎます。必要に応じてウィンドウも最大化してください。
- 画像を見ながら座標を合わせる検証ではShowSizeを1280x720に揃えます。なお通常Captureの保存サイズはShowSizeではなくカメラ取得画像のサイズです（取得1280x720なら保存も1280x720）。AreaCaptureは表示座標を取得画像の座標へ変換します。

画面解像度や拡大率によって収まる範囲は変わります。No2の1920x1080環境では、最大化・ShowSize1280x720・移動モードONでCommands最下段まで表示できることを確認しています。
