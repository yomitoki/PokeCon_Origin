# Stepデバッグアシスト 使い方

この機能は、シナリオの問題箇所まで何度も戻る作業を減らすための調整用機能です。

## いつもの操作順

1. CommandsAssist の「かんたんStepデバッグ」を開きます。
2. 「① 停止地点を追加」で Commands、状態変数、Step名を選びます。
3. 「この設定を有効」にして、通常どおり Commands を Start します。
4. 指定Stepの関数に入る直前で自動停止します。
5. 一覧の上から「③ 選んだ1個を実行」で動作を確認します。
6. 修正したい処理は「選んだ処理を修正」または「PC操作記録で置換」を使います。
7. 調整中の置換案はInputSetのStepデバッグ設定へすぐ保存され、元のPythonソースは書き換えません。
8. 行ごとの調整が終わったら「関数にまとめて実動作試験へ」を押します。
9. 自動的に開く「関数置換マッピング」で、関数全体の差分と「実動作試験ON」を確認します。
10. CommandsをStopしてもう一度Startします。同じStepではデバッグ停止せず、置換後の関数を通常速度で実行します。Pythonソースはまだ変更しません。
11. 実動作に問題がなければ「差分どおりソースへ本反映」を押します。

関数置換マッピングの実動作試験は、上部のCommandsAssist監視チェックとは別です。「実動作試験ON」の関数はCommands開始時に直接組み込まれ、実際にそのStepを通過すると一覧が「確認済」になります。到達していない場合は「未実行」のままです。

## 停止していない関数の置換案を確認する

CommandsAssistの「保存済み置換案」を開きます。Step名やコードで検索し、元処理と置換後処理を左右で比較できます。ここから編集、コピー、試験ON/OFF、削除ができます。

ソース変更後に古い処理IDが見つからない場合は「元処理を再指定」を押し、現在の関数内の処理一覧から正しい行を選び直します。選択中の元コードは下側へ全文表示されます。内容を確認して「選んだ1件を元処理として設定」を押してください。安全のため自動では別の行へ紐づけません。

## Pythonソースへ本反映する

1. 関数置換マッピングで実動作試験済みの関数を選び、表示された差分を確認します。
2. 「差分どおりソースへ本反映」を押します。
3. サンプル関数が見つかった場合は、反映範囲を選びます。
4. 最終確認の差分を確認します。
5. 「バックアップを作成して本反映」を押します。

反映前に `.stepdebug_日時.bak` を作ります。反映した置換案は削除せず、本反映履歴を残して試験OFFにします。

### サンプル関数の反映範囲

- **このCommandsだけに反映（推奨）**: 確認した使用箇所だけを変更し、共通サンプルと他の使用箇所は維持します。特定箇所だけ角度や時間が違う場合に使います。
- **共通サンプル本体と現在のCommandsへ反映**: 共通処理そのものの修正と判断できた場合に使います。他の既存Commandsへは自動展開せず、DevStudioで確認してから使用箇所へ反映します。

特定箇所の調整では、すぐにサンプル関数を改名・複製しません。まず対象Commandsだけに反映して試験し、共通化できると確認できた時点でサンプル本体へ昇格させます。これにより同名サンプルを大量に増やさず、他の正常な使用箇所も変更しません。

## ボタンの違い

- **1個を実行**: 選んだ行だけを試します。
- **続きの1個を実行**: 未実行の先頭行を1件実行します。画面を閉じて再表示した場合も、このボタンで続きへ戻れます。
- **ここまで実行**: 未実行の先頭から選択行まで順番に試します。
- **処理を修正**: 調整用コードを保存し、以後の試験で使います。
- **元処理／保存されている置換内容**: 一覧で選んだ行の元コードと置換コードを左右に全文表示します。PC操作記録の場合は記録名と変換後コードを表示します。
- **置換内容をコピー**: 右側に表示中の置換コードまたはPC操作記録の変換内容をクリップボードへコピーします。
- **PC操作記録で置換**: 登録済みのコントローラー記録をその行の代わりに再生します。
- **今からPC操作を記録**: 停止中のままPCゲームパッドで代わりの操作を行い、その記録を選択行の一時置換として保存します。
- **試験に使用 ON／OFF**: 保存した置換案を次の試験で使うか、元処理を使うか切り替えます。OFFでも置換案は削除されません。
- **保存置換 試験ON／OFF（①側）**: 選んだ停止地点に保存された置換案を、次の最初からの試験ですべて使うか切り替えます。実行前に変更できます。
- **実行・次Stepの「大丈夫ですか？」確認を省略**: チェックすると、処理実行、次Step移動、元関数実行のたびに出る確認だけを省略します。指定Stepへ到達したときの停止画面は省略しません。
- **置換案を削除**: 保存した置換内容を削除します。
- **選んだ1件をソースへ本反映**: 保存済み置換案の子処理を1件だけ選び、差分確認とバックアップ作成後にその変更だけを反映します。
- **関数にまとめて実動作試験へ**: 試験ONの行置換を関数全体へまとめ、関数置換マッピングへ登録します。ソースを変えずに通常Commandsで試験できます。
- **実動作試験 ON／OFF**: 関数置換マッピングにまとめた関数を、通常Commands開始時にメモリ上だけで置換するか切り替えます。
- **差分どおりソースへ本反映**: 実動作試験に使ったものと同一の関数差分をPythonソースへ反映します。
- **次Stepへ進む**: 元関数は実行せず、選んだ次状態を返します。
- **元関数を実行**: 手動調整を終え、元の関数を最初から通常実行します。

## 注意

- IF条件内の処理は、条件名を一覧に表示します。手動実行時は、現在のゲーム状態に合う処理だけを選びます。
- 現在位置は③の上に「先頭から何件完了・次は何番」と表示します。Stepデバッグ画面だけを閉じてもCommandsの停止状態と進捗は保持されます。
- PokeConまたはCommandsを終了すると実機の進捗はリセットされますが、置換案と試験ON/OFFはInputSetに残ります。
- 「停止地点 有効／無効」は停止するかどうか、「保存置換 試験ON／OFF」は保存した置換を試すかどうかの設定です。
- 指定Stepへ到達したときは、Commandsの処理を止めて「かんたんStepデバッグ」画面を表示します。確認省略をチェックしていても、この停止画面は表示します。
- ローカル変数に依存する処理は単独実行できない場合があります。その場合は、必要な値を `self.xxx` または数値に置き換えて保存します。
- サンプル本体を更新しても他の既存Commandsは自動変更しません。全使用箇所への展開はDevStudioのサンプル関数チェックから明示的に行います。
# 処理削除・関数単位の確認

- 移動回数が減り不要になった処理は、対象行を選んで`選んだ処理を削除`を押します。
- 実動作試験ではその処理を実行しません。
- ソースへ本反映する際は、Pythonのブロックを壊さないよう`pass  # PokeCon Stepデバッグ: 処理削除`へ置き換えます。
- `保存済みStepデバッグ置換案`では、同じ関数の変更が`＋`の親行へまとまります。
- 親行を選ぶと変更前と変更後の関数全体を左右で確認できます。
- `関数全体の差分を表示`で、追加行と削除行を色分けした差分を確認できます。
- `この関数の変更をまとめてソースへ本反映`は、その関数に保存された試験ONの変更だけを一括反映します。

`次Stepも続けて停止`で先へ進んだ場合は、Stepごとに別の保存枠を自動作成します。旧版で複数関数が1つのStepへ混在した記録は、起動時に状態テーブルと保存行番号から関数別へ分離します。
