# Commands監視録画の使い方

これは`Step / command variable segments`とは別の録画モードです。

- `Variable segments`は、指定した1つ以上の変数が開始値・終了値になった区間を録画します。
- `Commands監視録画`は、Commands内のすべての`STATE_*_FUNCTION`とStepを自動監視し、問題発生前の録画を残します。

## 基本操作

1. Cameraでゲーム映像を表示します。
2. Recordingを開き、`Commands監視録画`タブを選びます。
3. `Commands Start時に自動で監視開始`をONにします（既定でONです）。
   不要な録画を実行ごとに整理する場合は、`Commands Stop時に今回の仮録画を削除確認`もONにします。
4. Commandsタブから通常どおりStartします。
5. 監視録画は指定秒数ごとの動画、`steps.jsonl`、`commands.log`へ自動分割されます。

録画ボタンを先に押し、`Commands開始待ち`にしてからStartすることもできます。

## 保持方法

- 直近の異なるStepを既定で5個保持します。
- 同じStepが長く続く場合は、既定で直近180秒を保持します。
- `A → B → A → B`は2種類のStepとして扱います。
- 同じ並びを既定で3周検出するとループと判断し、最初の3周と直近3周を保持します。
- ループを正常に抜けると、最初側のループ一時保持を解除します。
- 保持対象から外れた一時録画は、MP4保存処理が終わってから自動削除します。

## 問題が起きた場合

- `現在保持を保護`: 表示中の録画をすべて自動削除対象から外します。
- `調整停止＋保護`: 録画を保護してからCommandsへ通常Stopを送ります。
- `選択の保護切替`: 一覧で選んだ録画だけを保護または解除します。
- `一時分を破棄`: 保護していない録画を削除します。

Commandsが例外終了した場合は、現在の動画を閉じて確認待ちにします。

StopまたはForce stopで明示的に停止し、`Commands Stop時に今回の仮録画を削除確認`がONの場合は、今回の実行で作成した未保護録画だけを削除するか確認します。

- `はい`: 今回の未保護録画だけを削除します。
- `いいえ`: 今回の分割録画を映像・音声・Step履歴・Outputログごと1本へ結合して保持します。
- `調整停止＋保護`: 削除確認を省略し、今回分を1本の保護録画へ結合します。

結合はバックグラウンドで行います。成功するまで元の分割録画は削除しません。結合に失敗した場合も元録画を残します。

## 保存ファイル

各録画フォルダには次を保存します。

- `recording.mp4`（変換中は`recording.avi`）
- `recording.wav`（音声入力がある場合）
- `steps.jsonl`（時刻、状態変数、Step遷移）
- `commands.log`（選択Outputの末尾ログ）
- `command_monitor.json`（保持状態、対象Commands、録画時間）

Stop時に保持した場合は、末尾が`_Commands_merged`のフォルダへ上記内容を1組にまとめます。

保存先、容量制限、映像＋ログ表示設定は通常Recordingの設定を共通利用します。監視録画の分割・保持設定はInputSetごとに保存されます。

## 主なStepの表示

- 一覧には、外側のMAINから現在実行中のSTORY、内部ステートマシンまでを `>` でつないで表示します。
- 初期化されただけで実行されていない兄弟ステートマシンの `*_START` は表示しません。
- 一覧は読みやすい実行経路だけを表示しますが、`steps.jsonl` には検出できた全状態変数を時刻付きで残します。

## 一時録画の自動削除

- 保護していない録画は、直近Step数、同一Stepの最低保持秒数、ループ保持数から外れると自動削除します。
- 前回起動時の一時録画も同じ条件で整理します。すべてを無期限には残しません。
- `保護` にした録画は自動削除しません。
