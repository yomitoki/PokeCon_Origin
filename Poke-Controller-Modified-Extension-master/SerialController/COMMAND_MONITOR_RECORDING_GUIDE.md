# Commands監視録画の使い方

これは`Step / command variable segments`とは別の録画モードです。

- `Variable segments`は、指定した1つ以上の変数が開始値・終了値になった区間を録画します。
- `Commands監視録画`は、Commands内のすべての`STATE_*_FUNCTION`とStepを自動監視し、問題発生前の録画を残します。

## 基本操作

1. Cameraでゲーム映像を表示します。
2. `Commands Start時に自動で監視開始`をONにします（既定でONです）。Recordingタブを開いていなくても有効です。
3. Camera・Audio・録画保存先を確認します。
4. Commandsタブから通常どおりStartします。
5. 監視録画は指定秒数ごとの動画、`steps.jsonl`、`commands.log`へ自動分割されます。

Commands実行中は、状態変数だけでなく実行中の関数とソース行も約0.1秒間隔で記録します。既存Commandsソースへ計測用コードを差し込まないため、通常の実行内容は変わりません。

録画ボタンを先に押し、`Commands開始待ち`にしてからStartすることもできます。

## 保持方法

- 問題Stepより前の異なるStepを既定で15個保持します。
- 同じStepが長く続く場合は、既定で直近180秒を保持します。
- `A → B → A → B`は2種類のStepとして扱います。
- 同じ並びを既定で3周検出するとループと判断し、ループ直前の異なる15 Stepと最初の3周だけを保持します。4周目以降の同じ映像は保存対象から外します。
- ループを正常に抜けると、最初側のループ一時保持を解除します。
- 画面が低輝度かつほぼ無変化の状態を60秒間検出した場合は、暗転・画面停止と判断します。問題Stepより前の異なる15 Stepと、停止開始から最大60秒の原因確認映像を保持します。それ以降の変化がない暗い映像は保存対象から外します。明るい静止メニューだけでは暗転扱いにしません。
- Commandsからキー・スティック送信がない場合は60秒間を復帰猶予として録画します。60秒以内に送信が戻れば通常監視へ戻り、戻らなければ問題Stepより前の異なる15 Stepと、最後のキー操作から最大60秒の原因確認映像を保持します。失敗確定後は状態監視だけを続けて動画書き込みを休止し、キー操作・画面変化・ループ脱出を検出した時点から新しい録画区間を開始します。
- 保持対象から外れた一時録画は、MP4保存処理が終わってから自動削除します。

## 問題が起きた場合

- `現在保持を保護`: 表示中の録画をすべて自動削除対象から外します。
- `調整停止＋保護`: 録画を保護してからCommandsへ通常Stopを送ります。
- `選択の保護切替`: 一覧で選んだ録画だけを保護または解除します。
- `一時分を破棄`: 保護していない録画を削除します。
- `動画・ソース比較`: 選択録画をDevStudioの専用タブで開き、動画時刻とStep・関数・ソース行を横並びで確認します。
- `Commands開発解析`: 動画・ソース比較から、STATE品質、ソース／実録画の遷移、変数変更、保存動画での画像検知をオフライン解析します。Commandsやコントローラー入力は実行しません。
- `復旧Python`: 実行中Commandsに対する復旧コードの作成画面を手動で開きます。Recordingタブだけでなく、Commandsタブの`復旧Pythonを開く`からも常に開けます。一度閉じた後も同じボタンから開き直せます。登録済みのお気に入りは一覧で選択して`選択を実行`を押すと、保存済みコードを読み込んでそのまま実行できます。編集してから実行する場合は`呼出`後に`Pythonを実行`を使用します。

### 復旧Python

`Stepループ・暗転停止で復旧Pythonを自動表示`がONの場合、監視録画のON/OFFにかかわらず、実際にCommandsをStartしている間だけ、Stepの同じ並びを3周、または暗い静止画を60秒検出すると別ウィンドウを開きます。Commandsを選択しただけの起動直後・未実行状態では、暗転検知を蓄積せず復旧画面も開きません。自動検出時は対象Commandsを現在のStepで一時停止し、保持中のボタン・スティックを解放します。映像変化が戻れば同じStepから自動再開し、暗転中でも［Commandsを再開］を押せば手動で再開できます。手動再開後も暗い静止画がさらに60秒続けば再度一時停止します。Commandsが画像一致を待つ間はコントローラー入力が60秒以上ない場合があるため、無入力だけでは一時停止も復旧画面の自動表示も行いません。無入力は監視録画の原因確認情報としてのみ記録します。

Commandsを実行しない機能制限版では、暗転・ループの検知、Commandsの一時停止、復旧画面の自動表示、Commands監視録画を実行しません。通常版へ戻した場合も、制限版になる前の暗転時間を持ち越さず0秒から監視します。

エディターでは通常のPythonに加え、`self`／`command`（実行中Commands）、`Button`、`Hat`、`Stick`、`Direction`、`press`、`press_rep`、`hold`、`release`、`stick`、`wait`、`image_check`、`release_all`、`log`を使用できます。復旧コードは停止中の別Commandsとして起動せず、元Commandsを同じStepで一時停止したまま、同じCommandsへの再指示として優先経路から送ります。復旧画面の開始・停止から元Commandsへ通常Stop／Force stopは送りません。コード内からも`finish()`、`end()`、`sendStopRequest()`、`force_stop()`など元Commandsの終了関数は実行できません。`復旧コードだけ停止`は復旧ワーカーだけへ停止要求を送り、入力と優先状態を解放した後も元Commandsの一時停止を維持します。元Commandsを終了する場合だけ、Commandsタブの通常Stop／Force stopを使用します。

`成功時にCommandsを自動再開`がONなら正常終了後に同じStep位置から再開します。コードエラー・実行停止時は一時停止を維持します。暗転中は成功してもすぐ再開せず、映像変化が戻ってから再開します。手動Pause、Software Controller、CommandsAssist、Stepデバッグなど別機能が所有している一時停止は、この画面から自動解除しません。

お気に入りは登録名とPythonコードを現在のInputSetへ保存できます。`新規登録`、`呼出`、`上書き変更`、`削除`を使用します。InputSet未登録の作業中設定は、InputSetの新規登録または変更保存で永続化されます。

`動画・ソース比較`では、保存された動画範囲に対応する実行経路だけを表示します。動画を再生またはシークすると、その時刻の実行行がソース上で黄色表示されます。`前の実行行`／`次の実行行`は経路を1件ずつ、`前の関数`／`次の関数`は関数の切替地点だけを移動し、動画も同じ時刻へ移動します。

PokeCon本体の`Command Watch`で変数を明示選択している場合、値が変化した時だけ、監視録画中の`steps.jsonl`へ`variable_watch`イベントとして保存します。Command WatchがOFF、監視録画が停止中、または値が同じ場合は書き込みません。DevStudioの`Commands開発解析…`にある`変数履歴`で、状態変数と一緒に動画時刻へ対応付けて確認できます。

録画画像検知の再現は既定600、最大2,000サンプルです。選択した全パターン×フレームは最大12,000照合とし、多数選択時はフレーム数を自動短縮します。処理は別スレッドで行われ、各検知の間でも`中止`を確認します。検知範囲、閾値、グレースケール、AND/OR、除外範囲は登録設定を使用し、結果を`command_image_profile.json`へ残します。

かんたんStepデバッグの停止地点は`step_debug_stop`として明示的に記録されます。DevStudioでは`停止Stepのみ`または`前/次の停止Step`で直接移動できます。

Commandsが例外終了した場合は、現在の動画を閉じて確認待ちにします。

StopまたはForce stopを押した時点でCommands監視録画は直ちに停止します。Commands側がループを抜けられず終了待ちになっても、録画だけが増え続けることはありません。ループまたは暗転・画面停止を検出済みの場合は、上記の判別用範囲へ絞ってから整理します。

自動判定前にStopした場合は、その時点のStepを問題Stepとして扱います。問題Stepより前の異なる15 Stepと、問題Step開始から最大60秒までを保存候補にします。

手動StopまたはForce stopでは、絞り込み後に残った今回の録画を必ず保存確認します。録画開始に失敗して保存候補が0本の場合も、無言で終了せず理由を表示します。

- `はい`: 今回の分割録画を映像・音声・Step履歴・Outputログごと1本へ結合し、保護して保存します。
- `いいえ`: 今回の未保護録画だけを削除します。
- `調整停止＋保護`: 今回分を先に保護し、Stop後に保護済みであることを表示して1本へ結合します。

結合はバックグラウンドで行います。成功するまで元の分割録画は削除しません。結合に失敗した場合も元録画を残します。

## 保存ファイル

各録画フォルダには次を保存します。

- `recording.mp4`（変換中は`recording.avi`）
- `recording.wav`（音声入力がある場合）
- `steps.jsonl`（動画時刻、状態変数、Step遷移、実行関数、ソース行、PC操作で割り込んだ入力）
- `command_image_profile.json`（DevStudioで録画画像検知を再現した場合だけ作成）
- `commands.log`（選択Outputの末尾ログ）
- `command_monitor.json`（保持状態、対象Commands、録画時間、ソース情報）
- `source_snapshots/`（録画時点のCommands／呼出先ソース。後で元ソースを編集しても比較できます）

Stop時に保持した場合は、末尾が`_Commands_merged`のフォルダへ上記内容を1組にまとめます。

## 入力記録の扱い

- Commandsが送ったボタン・スティック操作は、リンクされたソース行が根拠になるため、同じ内容を巨大な入力ログとして二重保存しません。
- Commands実行中にPCコントローラーで割り込んだ操作だけは`manual_controller_input`としてタイムラインへ追加します。
- PC操作から新しいCommandsを作る作業は、独立した`操作記録→Commands`タブを使用します。Commands録画の動画・ソース比較とは混在しません。

## 件数が多い場合

DevStudioのタイムラインは500件ずつページ表示します。1,000件や10,000件でも全件を一度にTreeviewへ描画せず、検索、停止Step絞り込み、前後ページ移動を使用できます。記録ファイル自体はJSONLへの追記式です。

保存先、容量制限、映像＋ログ表示設定は通常Recordingの設定を共通利用します。監視録画の分割・保持設定はInputSetごとに保存されます。

## 主なStepの表示

- 一覧には、外側のMAINから現在実行中のSTORY、内部ステートマシンまでを `>` でつないで表示します。
- 初期化されただけで実行されていない兄弟ステートマシンの `*_START` は表示しません。
- 一覧は読みやすい実行経路だけを表示しますが、`steps.jsonl` には検出できた全状態変数を時刻付きで残します。

## 一時録画の自動削除

- 保護していない録画は、直近Step数、同一Stepの最低保持秒数、ループ保持数から外れると自動削除します。
- 前回起動時の一時録画も同じ条件で整理します。すべてを無期限には残しません。
- `保護` にした録画は自動削除しません。
