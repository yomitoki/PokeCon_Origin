# Commands監視録画の使い方

これは`Step / command variable segments`とは別の録画モードです。

- `Variable segments`は、指定した1つ以上の変数が開始値・終了値になった区間を録画します。
- `Commands監視録画`は、Commands内のすべての`STATE_*_FUNCTION`とStepを自動監視し、問題発生前の録画を残します。

## 基本操作

1. Cameraでゲーム映像を表示します。
2. `Commands Start時に自動で監視開始`をONにします（既定でONです）。Recordingタブを開いていなくても有効です。
3. Camera・Audio・録画保存先を確認します。
4. Commandsタブから通常どおりStartします。
5. 監視録画は指定秒数ごとの内部録画チャンク、`steps.jsonl`、`commands.log`へ自動分割されます。PC保存では各チャンクをMP4に確定し、YouTube保存では区切り時間までAVI/WAVのまま保持します。

Recording上部で「録画なし」を選ぶと、通常録画とCommands Start時の自動監視録画は開始しません。Commands自体は通常どおり実行します。この選択はInputSetとRecordingセットに保存されます。

`録画保持モード`では次の2つを選べます。この選択もInputSetとRecordingセットに保存されます。

- `自動判定`: 直近Step、暗転・無操作、ループ前後を判定して必要な範囲だけを一時保持します。従来の既定動作です。
- `全区間を保持（録画用ループ判定・自動削除なし）`: 録画側ではStepループを判定せず、暗転・無操作による録画打切りや自動整理も行わず、Commands実行中を通常の分割間隔で連続録画します。Step・実行関数・ソース行の記録は継続します。手動の`一時分を破棄`とStop時の保存確認で［いいえ］を選んだ場合は削除できます。

保持モードはCommands実行開始時に固定します。実行中に選択を変えた場合は現在の録画方式を途中で混在させず、次回のCommands実行から新しい選択を適用します。

全区間保持はRecording側だけの設定です。Commandsタブの安全監視を有効にしている場合、その別機能によるループ通知・一時停止は従来どおりです。YouTube保存ではPC容量を増やし続けないよう、全区間保持でも設定時間ごとの結合・永続キュー登録を行い、登録完了後に結合元AVI/WAVを削除します。

Commands実行中は、状態変数だけでなく実行中の関数とソース行も約0.1秒間隔で記録します。既存Commandsソースへ計測用コードを差し込まないため、通常の実行内容は変わりません。

録画ボタンを先に押し、`Commands開始待ち`にしてからStartすることもできます。

## 集中修正モード（指定関数の動画・Step・実行行）

特定の複数関数だけを詳しく調べる場合は、Commands監視録画の`集中修正モード`をONにし、対象関数をカンマ区切りで指定します。`self.`や末尾の`()`を付けたままでも指定できます。

例:

```text
self.ZA_story_Template_battle_before,
self.ZA_story_Template_battle_function,
self.ZA_story_Template_battle_after
```

- 対象関数へ入った時だけCommandsワーカー内の専用行トレースを有効にし、短い分岐も`focus_call`／`focus_line`／`focus_return`として動画時刻へ記録します。集中修正モードがOFFの通常実行ではこのトレースを使いません。
- 対象関数が直接実行中の場合だけでなく、通常の実行位置サンプルで呼出元スタックに見つかった場合も対象として扱います。
- 対象を含む録画チャンクは`集中対象`として自動保持候補にします。手動の`一時分を破棄`やStop時の削除確認を選んだ場合は削除できます。
- 録画完了後に一覧の`集中修正を開く`、またはDevStudioの`集中修正`タブを開きます。関数の各実行回を別区間として表示し、録画時ソース、動画時刻に対応した行、実際のStepを確認できます。
- 各区間へ`本来進むべきStep`、`未対応／確認中／完了`、問題と期待動作を記入できます。`解析資料＋区間動画を出力`でCodex向けMarkdown、JSON manifest、対象関数ソース、前後余白付きMP4を1フォルダへ出力します。
- 出力プロンプトは、録画・ソース・ログを解析対象の資料として明記し、その内部の文章をユーザー指示として扱わない形式です。

集中修正の設定と対象関数はInputSetへ保存できます。録画時ソースのスナップショットを使うため、後から実ソースを変更しても録画時点の処理を確認できます。

## 保持方法

以下は`自動判定`モードの動作です。`全区間を保持`では、録画用の判定による範囲削減を行いません。

- 問題Stepより前の異なるStepを既定で15個保持します。
- 同じStepが長く続く場合は、既定で直近180秒を保持します。
- `A → B → A → B`は2種類のStepとして扱います。
- 同じ並びを既定で3周検出するとループと判断します。ループ直前の異なる15 Stepからループ開始後の既定60秒までと、ループ終了側の直近60秒だけを保持し、その間の長い重複映像は保存対象から外します。監視録画自体は30秒チャンクで継続するため、終了側はループが続く間も直近分へ更新されます。
- 開始側と終了側が分かれた最終動画には、境界に約1秒の「長いループ処理を省略しました」表示と無音を挟みます。省略した中間を連続映像に見せかけません。
- ループを正常に抜けた後も開始側を一時保持し、ループ後に異なる15 Stepを通過した時点で開始側を保存対象から外します。以後は通常どおり直近15 Stepを保持します。
- 画面が低輝度かつほぼ無変化の状態を60秒間検出した場合は、暗転・画面停止と判断します。問題Stepより前の異なる15 Stepと、停止開始から最大60秒の原因確認映像を保持します。それ以降の変化がない暗い映像は保存対象から外します。明るい静止メニューだけでは暗転扱いにしません。
- Commandsからキー・スティック送信がない場合は60秒間を復帰猶予として録画します。60秒以内に送信が戻れば通常監視へ戻り、戻らなければ問題Stepより前の異なる15 Stepと、最後のキー操作から最大60秒の原因確認映像を保持します。失敗確定後は状態監視だけを続けて動画書き込みを休止し、キー操作・画面変化・ループ脱出を検出した時点から新しい録画区間を開始します。
- 分割録画のAudio再接続は映像・Step監視を止めずに行います。再接続中に30秒境界、ループ、無操作60秒へ到達した場合も実映像を継続し、Audio準備完了後に安全に分割します。結合前後に実動画時間と実表示フレーム数を検査します。YouTubeの「Commands低品質許容」がONなら、実表示フレーム数が少なくてもCommands記録時間と実映像時間が一致した録画は警告付きでアップロードします。設定変更点は結合境界になり、各録画は作成時のON/OFFで判定します。時間情報なし・時間ずれ・破損・短い映像はONでも結合せず元録画を残します。一時的に読めないAVIは再試行し、同一ファイルを12回以上かつ5分以上読めない場合だけ異常区間として確認待ちにします。OFFとPC保存では従来どおり実表示フレーム不足も結合成功扱いにしません。短いAudioは無音で補い、映像末尾をAudio長に合わせて切りません。
- PC保存で保持対象から外れた一時録画は、MP4保存処理が終わってから自動削除します。
- YouTube保存では、30秒の内部チャンクを1本ずつMP4に変換しません。区切り時間（既定120分）の対象AVI/WAVを直接1本のMP4へ結合し、そのMP4のアップロードジョブを共有永続キューへ登録した後だけ、結合元チャンクを自動削除します。

## 問題が起きた場合

- `現在保持を保護`: 表示中の録画をすべて自動削除対象から外します。
- `調整停止＋保護`: 録画を保護してからCommandsへ通常Stopを送ります。
- `選択の保護切替`: 一覧で選んだ録画だけを保護または解除します。
- `一時分を破棄`: 保護していない録画を削除します。
- `動画・ソース比較`: 選択録画をDevStudioの専用タブで開き、動画時刻とStep・関数・ソース行を横並びで確認します。
- `Commands開発解析`: 動画・ソース比較から、STATE品質、ソース／実録画の遷移、変数変更、保存動画での画像検知をオフライン解析します。Commandsやコントローラー入力は実行しません。
- `復旧Python`: 実行中Commandsに対する復旧コードの作成画面を手動で開きます。Recordingタブだけでなく、Commandsタブの`復旧Pythonを開く`からも常に開けます。一度閉じた後も同じボタンから開き直せます。登録済みのお気に入りは一覧で選択して`選択を実行`を押すと、保存済みコードを読み込んでそのまま実行できます。編集してから実行する場合は`呼出`後に`Pythonを実行`を使用します。

保護切替では画面上の状態を先に安全側（保護・削除禁止）へ変更し、録画数に比例する`command_monitor.json`の保存は専用workerで行います。保存中に同じボタンを連打しても重複処理せず、`調整停止＋保護`は全対象の永続化成功後だけCommandsへStopを送ります。保存に失敗した場合は保護状態を維持して削除せず、エラーを表示します。

### 復旧Python

Commandsタブの`自動一時停止・復旧Pythonの自動表示を無効にする（既定ON）`は、新規および従来のInputSetで既定ONです。ONの間は、Stepループや暗い静止画を検出してもCommandsを自動一時停止せず、復旧Python画面も自動表示しません。自動一時停止中にONへ切り替えた場合は、その自動一時停止を解除します。設定はInputSetへ保存されます。

このチェックがONでも、Commandsタブの`Pause`と`復旧Pythonを開く`は引き続き手動で使用できます。復旧Python内の`一時停止`、復旧コード実行時の一時停止、Software Controller、CommandsAssist、Stepデバッグなど、ユーザーが明示的に開始する機能の一時停止は変更しません。

従来の自動監視を使う場合だけチェックをOFFにします。監視録画のON/OFFにかかわらず、実際にCommandsをStartしている間にStepの同じ並びを3周検出すると復旧Python画面を表示しますが、この通知だけではCommandsを止めません。［次のループ終了で一時停止］を押した場合だけ、次の完全な周回境界で一時停止します。暗い静止画を60秒検出した場合はその場で一時停止し、保持中のボタン・スティックを解放し、復旧Python画面を表示します。映像変化が戻れば同じStepから自動再開します。無入力だけでは一時停止も自動表示も行いません。

Commandsを実行しない機能制限版では、暗転・ループの検知、Commandsの一時停止、復旧画面の自動表示、Commands監視録画を実行しません。通常版へ戻した場合も、制限版になる前の暗転時間を持ち越さず0秒から監視します。

エディターでは通常のPythonに加え、`self`／`command`（実行中Commands）、`Button`、`Hat`、`Stick`、`Direction`、`press`、`press_rep`、`hold`、`release`、`stick`、`wait`、`image_check`、`release_all`、`log`を使用できます。復旧コードは停止中の別Commandsとして起動せず、元Commandsを同じStepで一時停止したまま、同じCommandsへの再指示として優先経路から送ります。復旧画面の開始・停止から元Commandsへ通常Stop／Force stopは送りません。コード内からも`finish()`、`end()`、`sendStopRequest()`、`force_stop()`など元Commandsの終了関数は実行できません。`復旧コードだけ停止`は復旧ワーカーだけへ停止要求を送り、入力と優先状態を解放した後も元Commandsの一時停止を維持します。元Commandsを終了する場合だけ、Commandsタブの通常Stop／Force stopを使用します。

`成功時にCommandsを自動再開`がONなら正常終了後に同じStep位置から再開します。コードエラー・実行停止時は一時停止を維持します。暗転中は成功してもすぐ再開せず、映像変化が戻ってから再開します。手動Pause、Software Controller、CommandsAssist、Stepデバッグなど別機能が所有している一時停止は、この画面から自動解除しません。

お気に入りは登録名とPythonコードを現在のInputSetへ保存できます。`新規登録`、`呼出`、`上書き変更`、`削除`を使用します。InputSet未登録の作業中設定は、InputSetの新規登録または変更保存で永続化されます。

PokeConの`実行経路`タブとDevStudioの`動画・ソース比較`には、どちらにも`Commandsソース内のみ`があります。チェックすると、`PythonCommandBase.py`、`Window.py`などの共通基盤を除外し、録画対象のCommandsソースで実際に実行された行だけを表示します。PokeCon側で経路を保存した場合は、そのチェック状態をDevStudioの初期表示へ引き継ぎます。元の全経路は保存したままなので、チェックを外せば共通基盤を含む表示へ戻せます。DevStudioではこの設定を、タイムライン、動画再生時の実行行、`前の実行行`／`次の実行行`、`前の関数`／`次の関数`へ共通適用します。動画を再生またはシークすると、その時刻の実行行がソース上で黄色表示されます。

### 以前より手前で失敗した実行との比較

1. DevStudioの`動画・ソース比較`で今回の録画を開きます。
2. `過去実行と比較…`を押し、以前もっと先まで進めた録画を`基準`に選びます。
3. `Step差分を比較`を押します。
4. 最初の`今回は未到達`、`今回だけ（再試行候補）`、`Step不一致`から確認します。

同じStepへ戻るミス処理は通過回数を分けて表示します。差分行を選ぶと、両実行のStep開始画面、画面差分、記録時の関数差分、基準録画と現在の実ソースの差分を確認できます。新しい録画では`step_frames`のCamera生画像を使うため画像検知枠や録画ログ表示は含みません。更新前の録画は該当時刻の動画フレームで代用するため、録画設定によっては検知枠が含まれます。

関数を基準録画時へ戻す場合は`基準録画の関数へ戻す…`を使用します。対象は選択中の同名関数だけです。変更前の実ソースは`.pokecon-command-backups`へ保存され、確認後に実ソースが編集されていた場合は安全のため中止されます。

PokeCon本体の`Command Watch`で変数を明示選択している場合、値が変化した時だけ、監視録画中の`steps.jsonl`へ`variable_watch`イベントとして保存します。Command WatchがOFF、監視録画が停止中、または値が同じ場合は書き込みません。DevStudioの`Commands開発解析…`にある`変数履歴`で、状態変数と一緒に動画時刻へ対応付けて確認できます。

録画画像検知の再現は既定600、最大2,000サンプルです。選択した全パターン×フレームは最大12,000照合とし、多数選択時はフレーム数を自動短縮します。処理は別スレッドで行われ、各検知の間でも`中止`を確認します。検知範囲、閾値、グレースケール、AND/OR、除外範囲は登録設定を使用し、結果を`command_image_profile.json`へ残します。

かんたんStepデバッグの停止地点は`step_debug_stop`として明示的に記録されます。DevStudioでは`停止Stepのみ`または`前/次の停止Step`で直接移動できます。

Commandsが例外終了した場合は、現在の動画を閉じて確認待ちにします。

StopまたはForce stopを押した時点でCommands監視録画は直ちに停止します。Commands側がループを抜けられず終了待ちになっても、録画だけが増え続けることはありません。ループまたは暗転・画面停止を検出済みの場合は、上記の判別用範囲へ絞ってから整理します。

自動判定前にStopした場合は、その時点のStepを問題Stepとして扱います。問題Stepより前の異なる15 Stepと、問題Step開始から最大60秒までを保存候補にします。

手動StopまたはForce stopでは、絞り込み後に残った今回の録画を必ず保存確認します。録画開始に失敗して保存候補が0本の場合も、無言で終了せず理由を表示します。

- `はい`: 今回の分割録画を映像・音声・Step履歴・Outputログごと1本へ結合し、保護して保存します。
- `いいえ`: 今回の未保護録画だけを削除します。
- `調整停止＋保護`: 今回分を先に保護し、Stop後に保護済みであることを表示して1本へ結合します。

結合はバックグラウンドで行います。成功するまで元の分割録画は削除しません。結合に失敗した場合も元録画を残します。

## 保存ファイル

各録画フォルダには次を保存します。

- `recording.mp4`（PC保存のMP4確定後。YouTube保存の30秒内部チャンクは個別MP4を作らず`recording.avi`のまま保持）
- `recording.wav`（音声入力がある場合）
- `steps.jsonl`（動画時刻、状態変数、Step遷移、実行関数、ソース行、PC操作で割り込んだ入力）
- `command_image_profile.json`（DevStudioで録画画像検知を再現した場合だけ作成）
- `commands.log`（選択Outputの末尾ログ）
- `command_monitor.json`（保持状態、対象Commands、録画時間、ソース情報）
- `source_snapshots/`（録画時点のCommands／呼出先ソース。後で元ソースを編集しても比較できます）
- `step_frames/`（更新後の録画で、画像検知表示を合成する前のStep開始Camera生画像）
- `focus_repair_request.json`（DevStudioで保存した対象関数、区間メモ、本来進むべきStep）
- `focus_repair_exports/`（集中修正で出力したCodex用Markdown、manifest、関数ソース、区間MP4）

Stop時に保持した場合は、末尾が`_Commands_merged`のフォルダへ上記内容を1組にまとめます。

## 入力記録の扱い

- Commandsが送ったボタン・スティック操作は、リンクされたソース行が根拠になるため、同じ内容を巨大な入力ログとして二重保存しません。
- Commands実行中にPCコントローラーで割り込んだ操作だけは`manual_controller_input`としてタイムラインへ追加します。
- PC操作から新しいCommandsを作る作業は、独立した`操作記録→Commands`タブを使用します。Commands録画の動画・ソース比較とは混在しません。

## 件数が多い場合

DevStudioのタイムラインは500件ずつページ表示します。1,000件や10,000件でも全件を一度にTreeviewへ描画せず、検索、停止Step絞り込み、前後ページ移動を使用できます。記録ファイル自体はJSONLへの追記式です。

保存先、容量制限、映像＋ログ表示設定は通常Recordingの設定を共通利用します。「PCへ保存」「YouTubeへアップロード」「録画なし」と「Commands低品質許容」の選択もInputSetとRecordingセットに保存され、「録画なし」では通常録画とCommands自動監視録画の両方を抑止します。監視録画の分割・保持設定はInputSetごとに保存されます。

YouTube保存では、録画停止を待ちません。Commands実行中も30秒の内部チャンクをAVI/WAVのまま閉じ、設定した分数ごと（既定は120分ごと）に対象チャンクを直接1本のMP4へバックグラウンド結合し、区間ごとに永続アップロードキューへ逐次登録します。24時間連続実行中もこれを繰り返します。結合元AVI/WAVは、結合済みMP4のジョブが永続キューへ確実に登録された後に削除します。結合済みMP4はYouTube側の処理完了を確認するまでPC上に保持し、完了後に自動削除します。結合待ちとキュー登録の関係は各チャンクの`command_monitor.json`が復旧ジャーナルとして保持するため、異常終了後も未完了区間から再開できます。キュー状態が `invalid_grant` の場合は対象チャンネルを再認証してください。再認証後は、ローカル動画が残っている有効なキューを自動再開します。`quota_waiting`はYouTubeの日次動画アップロード枠の回復待ちです。「次回再試行」までは新規`videos.insert`だけを止め、既存upload URLの継続、既存YouTube IDの処理確認、完了済み動画のPC削除は継続します。「キュー状況…」では動画を開かず、各ジョブの録画時間帯、長さ、登録／更新時刻、試行回数を確認できます。

2時間区切りでは、結合元フォルダー実体の固定、結合前の復旧ジャーナル保存、結合、キュー登録、全結合元へのキュー情報保存をすべて専用workerで行います。画面側は状態表示と、永続化成功後の削除予約だけを行います。順序は`元フォルダーidentity固定 → 結合MP4作成 → uploaderから見えないlocal-commitキューを保存 → merged／全結合元へ最終キューパス・期待Job identityを保存（削除はまだ禁止） → キューを原子的に公開 → uploader起動 → 元チャンクの削除許可を保存 → 削除予約`です。旧バージョンのupload workerがすでに動いていても、`.json.local-commit`は列挙対象にならないため、復旧情報の保存前にアップロードを開始しません。途中で失敗した場合は元AVI/WAVを削除しません。キュー保存だけが失敗した場合も完成済みMP4を残し、2時間分を再結合せず同じMP4の登録を上限付きbackoffで再試行します。再起動時のキュー探索・登録・merged／source保存も画面外で行います。削除workerは固定済みフォルダーを同じ親内のランダムなtombstone名へ移し、移動前後にフォルダー実体・キュー・結合済みMP4を再検証します。同じパスへ別フォルダーや別MP4が置かれた場合、または旧journalに必要なidentityがない場合は削除せず保持します。

削除予約だけでは空き容量は増えません。WindowsがAVI/WAVを実際に削除できた時点で初めて容量が空きます。ウイルス対策ソフトなどがファイルを一時使用中の場合は、元パスを同じ親フォルダー内の隔離名へ移して新しい録画と分離し、親フォルダー側の削除sidecarを使って低頻度で再試行します。途中まで削除して停止した場合やPokeCon／PCを再起動した場合も、隔離先の同一実体だけを復旧対象にします。元パスへ後から作られた別録画は削除しません。sidecarと隔離先は実削除成功後に整理されます。

Commands監視録画の開始準備（保存先作成、VideoWriter、開始journal）と再起動時の履歴探索も画面外で行います。準備中はCommands固有の録画監視だけを短時間待機させますが、Commands本体と独立した暗転・ループ安全監視は継続します。開始準備完了時の最新フレームと表示時刻から録画を始めるため、準備時間を欠落フレームとして大量補間しません。

録画停止時は、待機キューの件数だけでなく、表示時刻から必要になる残りCFRフレーム数を使ってwriterの待機時間を算出します。Audio停止にかかった時間は映像writerの待機時間から差し引きません。通常終了、手動Stop、監視停止、手動破棄のいずれもwriter待機は画面外で行うため、最大待機中もPokeCon画面と安全監視を固めません。Audioデバイスの停止処理で例外が起きても残りのAudio cleanupとvideo drainを続け、映像を閉じてからエラーを報告します。writerが安全に閉じられなかったチャンクは`recording_close_pending`／`recording_close_failed`として保護し、結合・アップロード・自動削除へ渡しません。旧バージョンで`recording`／`closing`のまま残った死んだownerのチャンクも、再起動時に同じ保護対象として読み込みます。

## 主なStepの表示

- 一覧には、外側のMAINから現在実行中のSTORY、内部ステートマシンまでを `>` でつないで表示します。
- 初期化されただけで実行されていない兄弟ステートマシンの `*_START` は表示しません。
- 一覧は読みやすい実行経路だけを表示しますが、`steps.jsonl` には検出できた全状態変数を時刻付きで残します。

## 一時録画の自動削除

- 保護していない録画は、直近Step数、同一Stepの最低保持秒数、ループ保持数から外れると自動削除します。
- 前回起動時の一時録画も同じ条件で整理します。すべてを無期限には残しません。
- `保護` にした録画は自動削除しません。
- `全区間を保持`で作成した録画は、再起動後や次のCommands実行でも自動整理から除外します。明示的な破棄、Stop時の削除選択、またはYouTube用結合を永続キューへ登録した後の元チャンク削除だけは実行します。
