# MEGA戦 mode 5 処理

`ZA_mega_evolution_battle_mode_select(mode=5)` は、最終戦専用入口
`ZA_mega_evolution_battle_mode5()` を経由して共通戦闘関数を呼びます。
mode 0～4の引数や既存の攻撃順とは分離しています。

## 手動調整する場所

`MEGA_MODE5_TESTMODE1_MANUAL_SETTINGS`で検索し、
`ZA_mega_mode5_testmode1_settings()`の辞書だけを変更します。
開始直後の緑床確認、HP75初期緑床の固定移動、緑床なし移動、移動後待機、HP別の青側障害物固定移動、
青／赤への固定向き直し、赤側障害物への固定移動、障害物内の定期回避、色切替条件が実行順に並んでいます。
現在のHP75手動値は、初期緑床確認回数／時間／待機が0、移動後待機4.5秒、障害物移動185度・5.0秒、向き直し30度です。
HP75以外は緑床を経由せず、障害物移動90度・1.4秒、向き直し90度です。
赤側障害物は、現在の実ソース手動値30度・6.2秒、向き直し140度です。青側から移る直前に90度へ非ロックオンYを3回行い、障害物に当てて開始地点を揃えます。青側・赤側の攻撃中は攻撃直前に270度へ0.5秒移動し、その後0.5秒待機します。青側では、この移動と待機の後にfresh frameで赤青敵の存在を確認します。
実行ソースを直接試した後も残す場合は、DevStudioの同名サンプル関数へ
同じ値を反映します。

## 状態遷移

```text
開始フラグ0: 開始直後／再挑戦選択後に状態をリセット
  ↓
開始フラグ1: FIELD / FIELD_BACK / 緑床 / BATTLE / 最終戦4技UIを確認
  ↓
開始フラグ2: GREEN_PRIORITY
  ├─ 緑床あり → GREEN_MOVE → GREEN_HOLD
  └─ 緑床なし → INITIAL_APPROACH（90度・最大強度）
  └─ 移動完了 → POST_MOVE_WAIT（通常2秒、現在のTESTMODE1手動値は0秒）
  ↓
開始フラグ3: FIELD_Wなら上入力、未確認FIELDなら左入力で再確認
  └─ 上入力5回後もFIELD_W → Xメニューを開閉してフラグ3から再試行
  ↓
開始フラグ4: TARGET_ATTACK
  ├─ 戦闘継続 → ターゲット探索・接近・攻撃
  ├─ TESTMODE1で赤敵だけを3秒・3回確認 → 赤側障害物へ固定移動・赤向きL／攻撃／Y
  ├─ 赤側障害物中に赤／青を見失う → RED_COVER_ATTACKを維持（自動復帰なし）
  ├─ 緑床移動／床上待機が成立 → LEGACY_COMBAT（BLACKCOMMENT／SELECTまで固定）
  ├─ 最終戦4技UI → 緑床優先確認 → ZL → A / X / B / Y
  └─ 黒コメント / 2・3相当の選択肢 → フラグ0
```

状態が変化すると、次の形式でログを出します。

```text
[MEGA_MODE5] GREEN_PRIORITY -> GREEN_MOVE :: green floor controls movement
[STATE_MAIN_FUNCTION][MEGA_MODE5] TESTMODE1=1 RESUME_HP=HP75 HP_COLOR=GREEN HP_RATIO=0.665 TEST_PHASE=HP75_EXISTING START_FLAG=2 PHASE=GREEN_MOVE DETECT=GREEN_FLOOR ACTION=move to green floor
```

通常の `STATE_MAIN_FUNCTION` 表示にも、開始フラグ、フェーズ、最後の検知、
最後の操作に加えて、試案の有効状態、再開時HP区分・色・比率、試案内の
処理フェーズを追加します。mode 5戦闘は完了まで外側のストーリーStepへ
戻らないため、戦闘中は状態変化時（同じ状態は5秒間隔）にmode 5側から
Commandsの状態表示欄を直接更新します。

## testmode1 試案（最終戦だけ）

- `testmode1` の既定値は0です。0なら従来のmode 5処理だけを通り、現在の`8_STORY_STORY_LAST_48`だけが試験用に1を渡します。結果が悪い場合はこの呼出値を0へ戻せます。
- 再開時は位置が固定されているため、現在の`INITIAL_GREEN_CHECK_COUNT=0`ではFIELD判定直後の緑床確認を行いません。FIELDを確認した同じ開始経路からHP別の固定移動へ進みます。通常戦闘中と予兆後の緑床処理はこの設定の対象外です。
- Switch No2の保存録画で3/4付近だった緑HPバーは、実測比率0.663～0.666でした。緑バー比率55～80%を`HP75`とし、この場合だけ90度・3秒の初期移動と4.5秒の待機を行い、その後、現在の手動設定185度・最大強度で5.0秒、青側障害物の端から少し内側へ回り込みます。
- HP75以外は再開時の緑床判定と90度・3秒初期移動を経由しません。FIELD判定後、`OTHER_COVER_MOVE_ANGLE=150.0`・最大強度で5.7秒の固定経路で、再開地点から青側障害物の少し内側へ直接移動します。汎用初期移動フラグも無効化するため、90度経路へのフォールスルーはしません。
- 障害物へ移動後はHP区分にかかわらず30度へ1.0秒移動してから`L`を1回送り、ロックオン攻撃へ移ります。障害物到達後も青色の一時的な画面位置で固定角度を上書きしません。以後、右側の「力をためた」または「強い光」を検知するまで、低レベルの再送を含めて右スティック視点探索と通常movemodeを止め、障害物から外れないよう通常左入力も停止します。
- 障害物待機中は2.4秒間隔でZLを解除し、障害物方向90度へ左入力を保持しながらYを2回送り、直後にZLを戻します。画面端の赤被弾回避も同じ方向へYを送ります。
- 青側障害物中は攻撃前の270度・0.5秒移動と0.5秒待機を終えた後、0.3秒以上の間隔でfresh frameの赤／青敵検知を試行します。障害物内で先に判定せず、視界が開いた攻撃位置を使用します。赤青とも見えない場合は`TESTMODE1_ENEMY_OCCLUDED`として青側を維持します。生の青候補1回でも赤のみ計測を止め、位置・面積を連続確認した確定赤だけを使用します。青側へ向いてLを入れた時点または最後の青候補から12秒間は潜行猶予として赤のみ計測を開始せず、その後さらに確定赤を3.0秒・3回以上確認した場合だけ`MOVE_TO_RED_COVER`へ進みます。赤側へ移る直前に90度方向へYを3回当てて青側障害物の移動開始点を固定し、そこから赤側障害物へ30度・6.5秒固定移動します。その後140度へ向いてL／ZL／攻撃と2.4秒間隔のYを継続します。赤側も通常の攻撃直前に270度へ0.5秒移動し、その後0.5秒待機します。
- 赤敵色を障害物越しに直接確認できない場合の代替として、1組目の「力をためた→強い光」が消えてから次の予兆セット開始までを青敵確認区間にします。この間、攻撃前fresh frameで青敵を一度も確認できなければ赤敵が残っているものと判断します。ただし2組目の予兆中には移動せず、その「強い光」が消えてから`WAIT_RED_COVER_DELAY`で5.0秒待機し、上下入力を追加せず`MOVE_TO_RED_COVER`へ進みます。途中で青を1回でも確認した場合は青側を維持し、次の予兆終了後から新しい確認区間を開始します。ログは`TESTMODE1_WARNING_BLUE_WINDOW_START`、`TESTMODE1_WARNING_BLUE_SEEN`／`TESTMODE1_WARNING_RED_PENDING`、`TESTMODE1_WARNING_RED_COVER_DELAY`→`TESTMODE1_WARNING_RED_COVER_WAIT`→`TESTMODE1_WARNING_RED_COVER_READY`です。
- 上記の予兆セット判定と、確定赤を3秒・3回確認する既存判定は残します。どちらも成立しない場合の保険として、青側`COVER_ATTACK`開始時または最後の青検知から60秒間青を検知できなければ、赤色の検知結果にかかわらず`MOVE_TO_RED_COVER`へ進みます。青を検知するたびに60秒タイマーをリセットします。ログは`TESTMODE1_BLUE_ABSENCE_WAIT`、`TESTMODE1_BLUE_ABSENCE_RESET`、`TESTMODE1_BLUE_ABSENCE_TIMEOUT`です。
- Switch No2録画では青敵が画面左端で欠けた際、検知ROI左境界へ接する輪郭の一律除外によって、生存中でも赤のみと判定されることを再現しました。左下UI除外は維持し、中段にある画面高10%以上の青輪郭だけ左境界接触を許可します。実録画フレームは修正前`red`、修正後`blue`となることを確認しています。この原因は60秒保険より先に既存の赤のみ判定を成立させ得るため、60秒は90秒へ変更していません。
- 開始フラグ3だけでなく、ロックオン・移動・攻撃中の開始フラグ4でも、倒れて`FIELD_W`が再表示された場合は上入力を再試行します。`FIELD_W`表示中は同時検知した`FIELD_BACK_W`より上入力を優先し、同じ周回のロックオン・移動・攻撃を一時停止します。`FIELD_W`が消えた後に戦闘処理へ戻ります。
- 赤側障害物へ入った後、位置・面積を連続確認した確定青を1.0秒・3回確認すると通常mode5へ戻します。赤と青は同時に存在し得るため、途中に確定赤が挟まっても青確認を取り消しません。赤青の生候補も20秒間まったく見えない場合も通常mode5へ戻し、BLACKCOMMENT／SELECT後の次回FIELDでTESTMODE1を再試行します。ログは`TESTMODE1_BLUE_RETURN_CHECK`／`TESTMODE1_BLUE_RETURN_LEGACY`、`TESTMODE1_RED_COVER_NO_ENEMY_CHECK`／`TESTMODE1_RED_COVER_NO_ENEMY_LEGACY`です。
- 緑床への移動または床上待機が一度でも成立したら、その場で`LEGACY_COMBAT`へ移行します。以後のFIELD再開ではTESTMODE1の青／赤障害物固定移動と定期Yを再開せず、BLACKCOMMENT／3_SELECT_TUTORIAL／3_SELECT／4_SELECTの検知時だけ固定を解除し、次のFIELDでTESTMODE1を再初期化します。
- 現在の`CHARGE_WARNING_SKIP_COUNT=-1`は、障害物攻撃中の「力をためた／強い光」から既存mode5の緑床／Y回避へ切り替えません。予兆表示は`CHARGE_WARNING_RED_ONLY_WAIT`として状態遷移を抑止しますが、青側・赤側双方の270度・0.5秒の攻撃前移動を「力をためた」の検知時点から止め、「強い光」の最終検知から7秒後まで停止します。CHARGEとSTRONG_LIGHTの間が7秒を超えても再開せず、強い光の表示中も再開しません。この間も青側・赤側共通の2.4秒間隔Yローリング2回は継続します。赤側移行は、確定赤の直接確認または上記の予兆セット間青不在判定で行います。
- 緑床成立で`LEGACY_COMBAT`へ移行した後は、`-1`でも既存mode5の「力をためた／強い光」検知、緑床移動、遠距離Y回避を有効にします。`CHARGE_WARNING_SKIP_COUNT`を0以上へ戻した場合は、指定回数を無視した次の予兆を受理します。
- HPバーが暗転などで見えない場合は0.25秒間隔・最大4回再確認します。最後まで不明でも棒立ちを避けるため`OTHER`として試案を開始します。

## 緑床

- 戦闘再開直後の緑床判定は現在0回です。通常戦闘中と「力をためた／強い光」後は緑床を優先し、実際の床移動／床上待機に入った時点でTESTMODE1を終了して通常mode5へ移行します。
- `TESTMODE1 + HP75 + 再開直後`の90度固定は緑床検知方向ではなく、位置が固定された再開地点からの初期移動です。通常戦闘中と「力をためた／強い光」後の緑床移動は、従来どおり検知した床位置から移動角度を計算します。
- `INITIAL_GREEN_CHECK_COUNT`を将来1以上へ戻した場合だけ、HP75再開でその回数の緑床確認を行います。画像処理が重い場合の実時間上限は`INITIAL_GREEN_CHECK_SECONDS`です。
- 再開画面上部のボスHPが黄色でおよそ1/4（実録画の約35.5%を含む20～42%）まで減っていても、初期移動は通常と同じ90度です。この判定はロックオン後の距離維持にだけ使用します。
- 黄色低HPは再開検知の1フレームだけで決定しません。暗転や選択肢からの切替でHPバーが隠れている場合に備え、初期移動後の待機中まで最大4回再判定します。一度一致したらその再開中は判定を保持します。
- 黄色低HPを含め、再開直後は緑床を確認しません。戦闘開始後または予兆後に緑床を検知した場合だけ、従来どおり緑床への移動を優先します。
- 緑床までの接近中は左スティックを強度1.0で保持します。0.1秒ごとの再判定では方向だけを更新し、中立入力を挟みません。
- 緑床方向を停止後のfresh frameで確定し、移動直前にも指定視点回転とマーカー探索の右スティックを停止します。緑床へ移動している間は視点回転を再開しません。
- 移動時間は画面上の床までの距離から算出し、最大3秒です。
- 足元の緑床を連続2回確認したら `GREEN_HOLD` へ移ります。移動終端で床上判定を取りこぼした場合も同様です。
- 通常の `GREEN_HOLD` は左スティックを中立にして2.5秒停止し、床表示が残っていても戦闘へ必ず戻ります。
- 2.5秒後は同じ床を再取得せず、床が0.6秒連続で消えた後に次の緑床候補を許可します。これにより、緑色の誤検知が残る場合も停止ループになりません。

## 最終戦の「強い光」予兆

- mode 5かつ`Z_Gaurd=1`の戦闘中だけ、`POKEMON_ZA_LAST_BATTLE_CHARGE`（「力を溜めている」）と`POKEMON_ZA_LAST_BATTLE_STRONG_LIGHT`（「強い光を放つ」）を確認します。
- 「力を溜めている」を検知した時点で通常攻撃と左移動を止め、最大3.5秒だけ緑床を探します。
- 緑床までの算出移動時間が1.35秒以内なら近距離と判断し、既存の`GREEN_MOVE`／`GREEN_HOLD`へ移ります。強い光の予兆経由の`GREEN_HOLD`だけは緑床が0.6秒連続で消えるまで維持します。
- 緑床が見えても1.35秒を超える遠距離なら、間に合わない床として直ちにZLを解除し、Y回避を7秒間維持します。
- 床を見つけられない間は、保存中の一方向へ右スティックを0.12秒だけ動かして再確認します。通常探索の強度約0.48より少し速い約0.58とし、次周の停止後fresh frameで緑床を判定します。時間だけで左右を交互に切り替えません。
- 「強い光を放つ」を検知するか3.5秒の探索期限に達した場合、ZLを解除し、左移動と視点を止めてYを3秒間送ります。完了後はZLだけを戻し、古い壁方向の左移動は復帰しません。
- 同じ通知が画面に残っている間の再発動は防止し、通知消失後の次の予兆から再度有効になります。
- 登録画像は保存済みSwitch No2録画から切り出し、閾値0.78、検知範囲`[840,170,1275,360]`です。

## ターゲット探索と移動

- ターゲットマーカーを優先し、取れない場合は赤／青の敵領域を補助判定に使います。
- mode 5の直接マーカー照合では、左下の手持ちポケモン固定UI（1280×720基準で`x<430, y>=500`）を候補から除外します。UI内の青緑輪郭をロックオンマーカーとして保存せず、右スティック探索を止めません。
- 赤と青が同時に有効候補になった場合は青を優先します。青候補がない場合だけ赤へ戻します。
- 赤／青補助は、開始フラグ4かつ直近1.5秒以内に `BATTLE` / `FIELD_W` / `FIELD_BACK_W` / HARD FIELDのいずれかを確認した場合だけ有効です。コメント・選択肢・暗転では期限を即時破棄します。
- 色は狭いHSV範囲だけでなくBGRの赤／青優勢度、明度、彩度、輪郭内比率、形状を併用します。上部HP・下部手持ち／技UI、暗い青背景、全画面寄りの攻撃発光は候補から除外します。
- 実マーカー／C+／EYEによるロックオン確認がない色候補は、同色・近い位置・近い面積を3回連続確認してから採用します。
- 確定した色候補はPokeConプレビューへ600ms表示します。赤敵は赤枠、青敵は青枠です。
- 左スティックは検出方向へ強度1.0で保持し、短い `press` の反復による減速を避けます。
- マーカー未検知中も最後の左右方向を保存し、同じ向きへ右スティック探索を続けます。時間だけでは左右を反転しません。
- マーカー未検知中の右スティックは0.70秒保持し、0.45秒の再ロック確認を挟んで同じ方向へ戻ります。
- ロックオン未確認で赤／青だけを取れた場合は、その色位置方向へ左スティック強度1.0で移動します。
- 実マーカー／C+／EYEによるロックオン確認中に赤／青が見えた場合は、遠距離では`dir1`（mode 5では20度）・強度1.0を維持します。敵中心が画面下寄り、または輪郭が大きい近距離では20／160度の横移動へ切り替え、敵へ直進し続けず攻撃距離を残します。この場合はZLの解放・再入力も行いません。
- 黄色HP約1/4で再開した区間だけ、実マーカーまたは赤／青補助と画像ロックオンが成立した後の90度接近を無効にします。敵が近い間は通常方向が0度付近なら300度（反対側は240度）の斜め後方へ移動し、ターゲット中心Yが420以上で後退開始、360以下で距離確保とします。境界間では直前状態を保つため、1フレームの位置揺れで方向を往復しません。距離確保後は0～20度（反対側は160～180度）の横移動へ切り替え、A／C+攻撃を継続します。一度ロックオンした後は、マーカーの短い未検知や赤青の色検知だけになっても、従来の55／125度や色位置由来の約60～90度の接近には戻らず、20／160度の距離維持で再捕捉を待ちます。一度もロックオンしていない間だけ、再捕捉に必要な接近を許可します。

## 攻撃

- AはC+画像がなくても安全な戦闘画面で継続します。
- C+またはC+_LOWを確認できた場合はPLUSを先に押し、B/X/Yも技入力として使用します。
- 最終戦固有の4技UIにはC+がありません。Switch No2の実フレームから切り出した「コアパニッシャー」「サウザンアロー」「サウザンウェーブ」「グランドフォース」を`POKEMON_ZA_LAST_BATTLE_MOVE_UI`の4パターン（OR、各閾値0.8）として確認します。
- 4技UIを確認した場合だけ、通常C+分岐を迂回して右視点を停止し、ZLを保持してA→X→B→Yを送ります。PLUSは送りません。各ボタン直前に4技UIを取り直し、画面が切り替わった時点で残り入力を止めます。
- 通常mode5では4技UIと緑床が同時なら緑床移動／待機を先にします。TESTMODE1の障害物待機中だけは予兆前の通常緑床割込みを抑止し、障害物内から4技入力を続けます。
- C+画像を確認できないB/X/Yの順番はAへ戻します。これによりBダッシュやYローリングを防ぎつつ攻撃回数を維持します。
- C+を一時的に取れなくても、安全な戦闘画面を確認できる場合はAを継続します。
- コメント、選択肢、暗転中にはAを送りません。
- mode 5では画面端2辺以上の赤い被弾表示を検知すると、緑床を再確認します。緑床への移動中／床上待機中はそちらを優先し、ZL解除やY回避を挟みません。
- 緑床処理が不要な場合だけZLを解除し、Yを6回送ってからロックオンと継続移動を復帰します。同じ赤表示中は再実行せず、赤が消えた後の次回被弾で再度有効になります。
- mode 0～4では従来のRCLICK後35秒の攻撃継続を維持します。C+を取れない通常区間の追加フォールバックもAだけに限定します。

## ポケモンを出せない場合の復旧

- mode 5の開始フラグ3または戦闘中のフラグ4で`FIELD_W`が残った場合、`Lbutton_up`を0.3秒以上の間隔で最大5回送ります。
- 5回後も`FIELD_BACK_W`へ変わらず`FIELD_W`が残る次周期で、左移動、視点探索、ZLを止めてXを1回送ります。
- `POKEMON_ZA_X_MENU_OPEN`を確認できた場合だけBを最大3回送り、メニューを閉じます。X入力を取りこぼしてメニューを確認できない場合は、戦闘中のB入力へ化けないようBを送りません。
- 白／緑／黒Comment、3_SELECT_TUTORIAL、3_SELECT、4_SELECTを確認している間はX/B復旧を保留します。
- 復旧周期中は攻撃処理へ進まず、上入力回数をリセットして開始フラグ3からポケモン選択をやり直します。mode 0～4には適用しません。

## 主な実装関数

- `ZA_mega_mode5_begin_resume`: 再開時の状態初期化
- `ZA_mega_mode5_testmode1_warning_cycle_update`: 2組の予兆間に青敵を確認できたかと、強い光消失後の5秒待機を管理

- `ZA_mega_mode5_green_and_initial_update`: 緑床優先と初期接近
- `ZA_mega_mode5_begin_post_move_wait`: 初期移動後の2秒待機
- `ZA_mega_z_guard_update`: 緑床への接近と床上待機

- `ZA_mega_movemode_update`: ターゲット探索と強度1.0の継続移動
- `ZA_mega_a_attack_ready`: A攻撃の安全なフォールバック
- `ZA_mega_mode5_skill_attack_ready`: C+確認済みB/X/Yの入力許可
