# MEGA戦 mode 5 処理

`ZA_mega_evolution_battle_mode_select(mode=5)` は、最終戦専用入口
`ZA_mega_evolution_battle_mode5()` を経由して共通戦闘関数を呼びます。
mode 0～4の引数や既存の攻撃順とは分離しています。

mode 5ではRPush画像をSELECT、Comment、TESTMODE1より先に確認し、
敗北黒背景でない実RPushならその周回でRClickを入力します。
入力直後は`RPUSH_FIELD_WAIT`へ入り、`POKEMON_ZA_FIELD_W`、
`POKEMON_ZA_FIELD_BACK_W`、`POKEMON_ZA_NO_BATTLE_FIELD_HARD_CHECK`を
復帰条件として確認します。同じFIELD画像を3周連続確認するまで左スティック、
視点、ZLを解除し、敵色、通常攻撃、移動、強い光の実処理を行いません。
ただし他の無期限FIELD待機と同じく、固有4技UI、Xメニュー、厳密な敗戦条件、
FIELDなし180秒後の名称イベント判定は割込みとして確認します。
RPush直前の`COVER_ATTACK`、`RED_COVER_ATTACK`、`BLUE_CHASE_ATTACK`、
`FREE_RUN`、`LEGACY_COMBAT`を保存し、FIELD確定後に同じフェーズへ戻します。
RPush中に新たなフリーランへは移行しません。RPush前がフリーランだった
場合だけ、FIELD復帰後にフリーランを再開します。`FIELD_W`の必要な
上入力後、保存した青／赤側の90度へ0.2秒だけ短く復帰移動し、
`begin_resume()`や障害物初期経路は再実行しません。

mode 5でFIELDが見えているのに確認済み攻撃が300秒なく、同じ間
`POKEMON_ZA_LAST_BATTLE_CHARGE`／`POKEMON_ZA_LAST_BATTLE_STRONG_LIGHT`
も一度も見えない場合は救済遷移を検討します。予兆を見たら300秒を
計り直します。発火時にボスHPが緑80%超と再確認できれば適用し、HPが
読めない場合はFIELDが見えている時だけ補助判定します。
黄色など低HPが実測できた場合は適用しません。再戦メニューの選択位置は
HP引継ぎ／全快の根拠として使用しません。
イベント攻撃の4技UIやESCAPEだけでは300秒計測を開始せず、その後の
バトルでFIELDを確認してから開始します。青／赤障害物越し、または安全
画面で送っただけのAは攻撃成立を保証しないため、時計をリセットしません。
ただしTESTMODE1の青側、赤側、赤から戻った青追跡中は、この300秒保険を
無効にします。側の移行は「強い光2セット」または「その側の実処理開始から
180秒（3分）」のどちらか早い方で専用判定へ進みます。この180秒時計は
300秒watchdogとは独立しており、RPush／FIELD待機／再戦後の初期移動時間を
含めません。
mode 5の画像取得は「固有4技UI → FIELD系／HARD FIELD／Escape → 敗北黒背景」の
順です。実入力は「固有4技UI → FIELD_W上入力（HARD／Escape共存可）→
FIELD_W不在時のHARD／Escape再戦」の順で処理します。
`Template/ZA_Story_PIC/Common/za_black_back.png`と左上912×536領域を
直接比較し、RGB各画素の差が24以下の画素が98.5%以上の状態を
5秒連続確認した場合だけ、敗北黒コメント／SELECTラッチを有効にします。
その5秒中はSELECT画像自体を照合しません。ラッチ後もFIELD_W、
FIELD_BACK_W、HARD FIELD、戦闘Lv、Escapeがすべて不在であることを
必須とし、SELECTは0.05秒後に再照合します。SELECT描画で黒背景が変わっても
5秒確定済みラッチは保持し、選択位置と入力順は従来ソースを維持します。
通常MEGA戦のSELECT判定は従来どおりFIELD／Lv／RPush除外を使います。
敗戦直後の「再挑戦しますか？」でSELECTもBLACKCOMMENTもまだ取れない場合は、
黒背景を5秒確定した後にAを1回送って再戦SELECTを表示します。Aは0.8秒間隔に
制限し、SELECTが表示された後は専用検知と従来の選択位置に戻ります。検知中は
`za_black_back.png`と同じ左上912×536範囲を赤枠で表示します。
黒Comment画像が一致してもこの黒背景が不一致の場合は、敗戦再開フラグを
初期化せず、移動・攻撃を止めてAで通常Commentだけを送ります。
番号付きSELECTは引き続き黒背景一致時だけ再戦入力として扱います。
イベント導入の正規暗転で5秒ラッチが立ったまま、FIELD／戦闘Lv／Escapeを
挟まずアンジュフラエッテ戦へ移る場合は例外です。実SELECT／黒Commentを
最優先で確認し、それらがなく`last_battle_name.png`が一致する場合は、黒背景単独の
一致にかかわらず敗戦Aを送らず、180秒を待ち直さず名称の新規5秒確認→ZL→
4技UI再確認へ進みます。名称確認・ZL・4技入力中に実SELECT／黒Commentが出れば
従来の敗戦処理を優先します。4技UIがなければ盲目Aを送らず、保存済みの直近
`COVER_ATTACK`／`RED_COVER_ATTACK`／`BLUE_CHASE_ATTACK`／`FREE_RUN`へ戻します。
保存フェーズがなければ`FREE_RUN`へ戻し、同じ名称表示中はZLを再送しません。
名称が0.5秒以上消えた後の次の表示だけ、改めて名称5秒確認を許可します。
名称5秒→ZL後に4技UIを一度確認できても、最初のA入力直前にUIが消えた場合は
入力0件として同じ直近フェーズ復帰へ接続します。Comment、Xメニュー、FIELD系、
Escape、RPushが割り込んだ場合は復帰せず、その画面を次周回の既存処理へ渡します。

## 手動調整する場所

`MEGA_MODE5_TESTMODE1_MANUAL_SETTINGS`で検索し、
`ZA_mega_mode5_testmode1_settings()`の辞書だけを変更します。
開始直後の緑床確認、HP75初期緑床の固定移動、緑床なし移動、移動後待機、HP別の青側障害物固定移動、
青／赤への固定向き直し、赤側障害物への固定移動、障害物内の定期回避、色切替条件が実行順に並んでいます。
現在のHP75手動値は、初期緑床確認回数／時間／待機が0、移動後待機4.5秒、障害物移動185度・5.0秒、向き直し30度です。
HP75以外は緑床を経由せず、障害物移動150度・5.7秒、向き直し30度です。
赤側障害物への固定移動は現在60度・7.5秒、向き直しは160度です。
青／赤側の移行判定時はそれぞれ90度へ非ロックオンYを2回行い、3秒待機します。
実行ソースを直接試した後も残す場合は、DevStudioの同名サンプル関数へ
同じ値を反映します。

## 状態遷移

```text
実入力優先度: 固有4技UI → FIELD_W上入力（HARD/Escape共存可）
              → FIELD_WなしのHARD FIELD / Escape
              → 黒背景5秒 AND（黒Comment または敗戦SELECT）
                AND FIELD_W / FIELD_BACK_W / HARD FIELD / 戦闘Lv / Escapeが全て不在
無期限FIELD待機: XメニューならB最大20回
  ├─ 古い敗戦ラッチ + 実SELECT/黒Commentなし + 最終戦名
  │    └─ 名称を新規5秒確認 → ZL → 4技UI再確認
  │         ├─ UIあり → 固有4技（入力成功時に古い敗戦ラッチ解除）
  │         └─ UIなし → 直近の青／赤／青戻り／FREE_RUNへ復帰
  └─ FIELDなし180秒 → イベント候補として最終戦名を確認開始
       └─ 最終戦名5秒 + FIELD系なし + Escapeなし → ZL → 4技UI再確認
            └─ UIなし → 直近フェーズ、保存なしならFREE_RUNへ復帰
       └─ 最終戦名なし → 敗戦にせず無期限FIELD待機を継続
開始フラグ0: 開始直後／再挑戦選択後に状態をリセット
  ↓
開始フラグ1: 固有4技UI / FIELD_W / HARD FIELD / Escape / 黒背景を上記順で処理
  ↓
開始フラグ2: GREEN_PRIORITY
  ├─ 緑床あり → GREEN_MOVE → GREEN_HOLD
  └─ 緑床なし → INITIAL_APPROACH（90度・最大強度）
  └─ 移動完了 → POST_MOVE_WAIT（通常2秒、現在のTESTMODE1手動値は0秒）
  ↓
開始フラグ3: FIELD_Wなら上入力、未確認FIELDなら左入力で再確認
  └─ 上入力5回後もFIELD_W → Xメニューを開閉してフラグ3から再試行
  ↓
開始フラグ4: TARGET_ATTACK
  ├─ 戦闘継続 → ターゲット探索・接近・攻撃
  ├─ 青側: 強い光2セット OR 青側実処理180秒 → 5秒 → 青角度Y×2 → 3秒
  │    └─ 通常C+なし + 青なし → 赤側障害物へ固定移動
  │    └─ 上記以外 → FREE_RUN
  ├─ 赤側: 強い光2セット OR 赤側実処理180秒 → 5秒 → 赤角度Y×2 → 3秒
  │    ├─ 通常C+なし + 赤なし + 青あり → BLUE_CHASE_ATTACK
  │    └─ 通常C+なし + 赤なし + 青なし → FREE_RUN
  │    └─ 上記以外 → FREE_RUN
  ├─ 赤から戻った青: 強い光2セット OR 青追跡実処理180秒
  │    └─ 5秒 → 青角度Y×2 → 3秒 → 敵色／通常C+確認後にFREE_RUN
  ├─ 通常経路の緑床移動／床上待機が成立 → LEGACY_COMBAT（BLACKCOMMENT／SELECTまで固定）
  ├─ FREE_RUN中の予兆から緑床移動／床上待機 → 完了後にFREE_RUNへ復帰
  ├─ 最終戦4技UI → ZL → A / X / B / Y
  │    └─ 1技以上入力 → 敗戦相当のRETRY_SELECTION／WAIT_RESUMEへ移行
  │         └─ 残存4技UI・180秒名称fallbackを無視してFIELD待機
  │         └─ FIELD_Wは上入力、FIELD_W消失後のHARD FIELD／Escapeで再戦初期化
  └─ 黒コメント / 2・3相当の選択肢 → FREE_RUNと予兆状態を解除してフラグ0
```

状態が変化すると、次の形式でログを出します。

```text
[MEGA_MODE5] GREEN_PRIORITY -> GREEN_MOVE :: green floor controls movement
[STATE_MAIN_FUNCTION][MEGA_MODE5] TESTMODE1=1 RESUME_HP=HP75 HP_COLOR=GREEN HP_RATIO=0.665 TEST_PHASE=HP75_EXISTING START_FLAG=2 PHASE=GREEN_MOVE DETECT=GREEN_FLOOR ACTION=move to green floor
```

通常の `STATE_MAIN_FUNCTION` 表示にも、開始フラグ、フェーズ、最後の検知、
最後の操作に加えて、試案の有効状態、再開時HP区分・色・比率、試案内の
処理フェーズを追加します。mode 5戦闘は完了まで外側のストーリーStepへ
戻らないため、戦闘中は状態変化時（同じ状態は5秒間隔）にmode 5側から
Commandsの状態表示欄を直接更新します。

## testmode1 試案（最終戦だけ）

- `testmode1` の既定値は0です。0なら従来のmode 5処理だけを通り、現在の`8_STORY_STORY_LAST_48`だけが試験用に1を渡します。結果が悪い場合はこの呼出値を0へ戻せます。
- 固有4技UIを毎周回最優先で確認します。UIがなく、`last_battle_name.png`が5秒連続表示され、FIELD_W／FIELD_BACK_W／HARD FIELD／Escapeがすべてない場合だけZLを入れ、0.3秒後に4技UIを再確認します。それでもUIがない場合、またはUIを一度確認しても最初のA入力前に消えた場合は盲目のAを送らず、保存した直近の`COVER_ATTACK`／`RED_COVER_ATTACK`／`BLUE_CHASE_ATTACK`／`FREE_RUN`へ戻します。保存値がなければ`FREE_RUN`へ入り、同じ名称表示中はZLを再送しません。
- 再開時は位置が固定されているため、現在の`INITIAL_GREEN_CHECK_COUNT=0`ではFIELD判定直後の緑床確認を行いません。FIELDを確認した同じ開始経路からHP別の固定移動へ進みます。通常戦闘中と予兆後の緑床処理はこの設定の対象外です。
- Switch No2の保存録画で3/4付近だった緑HPバーは、実測比率0.663～0.666でした。緑バー比率55～80%を`HP75`とし、この場合だけ90度・3秒の初期移動と4.5秒の待機を行い、その後、現在の手動設定185度・最大強度で5.0秒、青側障害物の端から少し内側へ回り込みます。
- HP75以外は再開時の緑床判定と90度・3秒初期移動を経由しません。FIELD判定後、`OTHER_COVER_MOVE_ANGLE=150.0`・最大強度で5.7秒の固定経路で、再開地点から青側障害物の少し内側へ直接移動します。汎用初期移動フラグも無効化するため、90度経路へのフォールスルーはしません。
- 障害物へ移動後はHP区分にかかわらず30度へ1.0秒移動してから`L`を1回送り、ロックオン攻撃へ移ります。青／赤側では強い光の表示→消失を移行用の1セットとして数えます。強い光が出ないHP最大開始も進行できるよう、同じ側の実処理を開始した時点から180秒（3分）の独立時計も開始し、強い光2セットまたは180秒のどちらか早い方を移行判定の入口とします。この側移行用チェックでは、フリーラン用の緑床探索や遠距離回避は行いません。
- 障害物待機中は2.4秒間隔でZLを解除し、障害物方向90度へ左入力を保持しながらYを2回送り、直後にZLを戻します。「力をためている」を検知したら通常攻撃と270度の攻撃前移動を止め、このY×2を即時実行した後も2.4秒間隔でローリングだけを継続します。強い光で待機を解除した後も7秒間は同じローリングだけの状態を維持します。CHARGEだけ一致して強い光が出ないまま側別180秒が成立した場合は、この強い光待ちと攻撃前blockを解除してから既存の側判定へ進みます。画面端の赤被弾回避も同じ方向へYを送ります。
- 青側では、強い光2セット完了または青側の実処理開始から180秒経過のどちらか早い方で入口条件を満たします。どちらの入口でも、その後は従来どおり5秒待機し、`BLUE_SIDE_TRANSITION_DODGE_ANGLE=90`でYを2回、3秒待機します。そのfresh frameで青敵が安定色／生候補のどちらにもなく、固有4技ではない通常C+／C+_LOWも表示されない場合だけ`MOVE_TO_RED_COVER`へ進みます。条件不成立時は強い光セットや180秒を数え直さず、視点回転・移動・攻撃と緑床処理を行う`FREE_RUN`へ入ります。移行成立後は、判定用Y×2とは別に従来の開始点調整を保ち、`BLUE_TO_RED_ANCHOR_DODGE_ANGLE=90`でYを3回障害物に当ててから、60度・7.5秒の赤側固定移動を行います。
- 赤側でも、強い光2セット完了または赤側の実処理開始から180秒経過のどちらか早い方で入口条件を満たします。その後の5秒、`RED_SIDE_TRANSITION_DODGE_ANGLE=90`のY×2、3秒、fresh frameでの敵色／通常C+確認は変えません。通常C+／C+_LOWが表示されず、赤敵なし・青敵ありなら`BLUE_CHASE_ATTACK`で視点回転・移動・攻撃を再開し、赤青ともなければ`FREE_RUN`へ入ります。赤が見える場合や通常C+が表示される場合など、条件不成立時も再計数せず`FREE_RUN`へ入ります。
- 赤側から戻った`BLUE_CHASE_ATTACK`でも、強い光2セット完了または戻った青追跡の実処理開始から180秒経過のどちらか早い方を使用します。その後は同じ5秒待機、青側角度Y×2、3秒待機、fresh frameでの敵色／通常C+確認を維持し、既存どおり`FREE_RUN`へ入ります。
- 側別180秒時計は`COVER_ATTACK`／`RED_COVER_ATTACK`／`BLUE_CHASE_ATTACK`の各実処理へ入ってから新規計時します。RPush演出とそのFIELD待機、再戦後のFIELD待機、HP判定、初期移動、障害物への移動は算入しません。側phaseの変更、再戦処理、SELECT処理、RPush処理、TESTMODE1のresetでは時計を破棄し、次の対象phaseで0から計り直します。この時計は無攻撃／予兆なしの300秒watchdogとも、無期限FIELD待機の180秒イベント判定とも別管理です。
- A攻撃は安全側の保険として許可しますが、X／B／Yの通常技攻撃は通常C+／C+_LOWなしで実行しません。
- 開始フラグ3と4に加え、再戦選択後の`nofiled=1`または`RETRY_SELECTION`に古い`nofiled=0`が残る待機中でも、`FIELD_W`が表示された場合は状態遷移をせず上入力を再試行します。0.10秒の上入力を0.3秒間隔・最大5回行い、`FIELD_BACK_W`で解除し、残存時のXメニュ復帰も従来どおりです。HARD FIELD判定と戦闘左端のEscapeアイコンはいずれも正常な`FIELD_W`と同時成立し得るため、共存時は既存の上入力を先に行い、`FIELD_W`消失後の次周回でHARD FIELD／Escapeの再戦処理へ進みます。固有4技UIは引き続き上入力より優先し、Escape単独時は従来どおり再戦処理へ進みます。
- RPush後、再戦選択後、開始フラグ3、緑Comment内部を含む無期限FIELD待機では、FIELD判定以外にXメニューを監視し、表示中だけBを同一エピソード合計20回まで送ります。黒背景単独では敗戦にせず、黒背景を5秒維持したうえで黒Commentまたは敗戦SELECTが確認でき、かつFIELD_W／FIELD_BACK_W／HARD FIELD／戦闘Lv／Escapeが全て不在の場合だけ敗戦処理へ渡します。
- 無期限FIELD待機でFIELDを確認できないまま180秒経過した場合は、敗戦タイムアウトではなくイベント候補の確認開始とします。180秒より前は`last_battle_name.png`自体を照合しません。180秒後に名称がなければ無期限待機を続け、名称を5秒連続確認できた場合だけZLを入れます。固有4技UIを再確認できた場合だけA→X→B→Yを送り、UIがなければ盲目Aを送らず直近の青／赤／青戻り／FREE_RUNへ復帰します。
- 黒背景5秒ラッチ後のBLACKCOMMENT／SELECT周回では、`WAIT_RESUME_HOLD`を先に実行せず、既存のComment送りと再挑戦SELECT入力へ到達させます。SELECTの選択位置・入力順は変更しません。その後はHARD FIELDまたはEscapeを確認した場合だけ再戦開始処理へ戻し、`FIELD_W`／`FIELD_BACK_W`だけでは戻しません。`RETRY_SELECTION`・`WAIT_RESUME`の明示状態はローカル`nofiled=0`が残っていても開始待機として扱い、左右移動・視点・ZLを止めたまま次の優先判定を続けます。
- 通常戦闘経路で緑床への移動または床上待機が成立した場合は、その場で`LEGACY_COMBAT`へ移行します。以後のFIELD再開ではTESTMODE1の青／赤障害物固定移動と定期Yを再開せず、BLACKCOMMENT／3_SELECT_TUTORIAL／3_SELECT／4_SELECTの検知時だけ固定を解除し、次のFIELDでTESTMODE1を再初期化します。ただし、実`FREE_RUN`中の「力をためた／強い光」から開始した緑床移動・床上待機は一時的な予兆処理であり、完了後は視点回転・移動・Aを行う`FREE_RUN`へ復帰します。再戦処理またはSELECT処理へ入るときは、FREE_RUN、予兆guard、予兆前フェーズ、関連タイマーを全て無効化し、次の再開へ持ち越しません。
- 「力をためた／強い光」の緑床探索・遠距離Y回避は、`_za_mega_mode5_free_run_active=True`の実フリーラン中だけ有効です。青／赤側では側移行用の強い光セット計数または側別180秒時計と、従来の障害物方向Y×2だけを行い、緑床探索には入りません。`LEGACY_COMBAT`、RPush後FIELD専用待機、FIELD確認後の短い復帰移動中にも起動しません。
- HPバーが暗転などで見えない場合は0.25秒間隔・最大4回再確認します。最後まで不明でも棒立ちを避けるため`OTHER`として試案を開始します。

## 緑床

- 戦闘再開直後の緑床判定は現在0回です。通常経路で緑床への実移動／床上待機が成立した場合は`LEGACY_COMBAT`へ移行します。青／赤側の強い光セットでは緑床処理を行いません。実`FREE_RUN`の即死予兆処理中だけ従来の緑床探索を使い、その経路の`GREEN_MOVE`／`GREEN_HOLD`完了後は`LEGACY_COMBAT`へ固定せず`FREE_RUN`へ戻ります。
- `TESTMODE1 + HP75 + 再開直後`の90度固定は緑床検知方向ではなく、位置が固定された再開地点からの初期移動です。実フリーラン中の緑床移動は、従来どおり検知した床位置から移動角度を計算します。
- `INITIAL_GREEN_CHECK_COUNT`を将来1以上へ戻した場合だけ、HP75再開でその回数の緑床確認を行います。画像処理が重い場合の実時間上限は`INITIAL_GREEN_CHECK_SECONDS`です。
- 再開画面上部のボスHPが黄色でおよそ1/4（実録画の約35.5%を含む20～42%）まで減っていても、初期移動は通常と同じ90度です。この判定はロックオン後の距離維持にだけ使用します。
- 黄色低HPは再開検知の1フレームだけで決定しません。暗転や選択肢からの切替でHPバーが隠れている場合に備え、初期移動後の待機中まで最大4回再判定します。一度一致したらその再開中は判定を保持します。
- 黄色低HPを含め、再開直後は緑床を確認しません。戦闘開始後または予兆後に緑床を検知した場合だけ、従来どおり緑床への移動を優先します。
- 緑床までの接近中は左スティックを強度1.0で保持します。0.1秒ごとの再判定では方向だけを更新し、中立入力を挟みません。
- 緑床方向を停止後のfresh frameで確定し、移動直前にも指定視点回転とマーカー探索の右スティックを停止します。緑床へ移動している間は視点回転を再開しません。
- 移動時間は画面上の床までの距離から算出し、最大3秒です。
- 足元の緑床を連続2回確認したら `GREEN_HOLD` へ移ります。移動終端で床上判定を取りこぼした場合も同様です。
- 通常の `GREEN_HOLD` は左スティックを中立にして2.5秒停止し、床表示が残っていても戦闘へ必ず戻ります。
- 2.5秒後は同じ床を再取得せず、床が0.6秒連続で消えた後に次の緑床候補を許可します。これにより、緑色の誤検知が残る場合も停止ループになりません。

## 最終戦の「強い光」予兆

- mode 5かつ`Z_Gaurd=1`で、300秒救済、青／赤側の移行条件不成立、または赤から戻った青で「強い光2セット OR 側別180秒」の入口後に既存判定を完了して実`FREE_RUN`へ入った後だけ、`POKEMON_ZA_LAST_BATTLE_CHARGE`（「力を溜めている」）と`POKEMON_ZA_LAST_BATTLE_STRONG_LIGHT`（「強い光を放つ」）による緑床探索・遠距離回避を処理します。青／赤障害物中はフリーラン処理ではなく、側移行用セット計数／側別180秒時計と通常攻撃停止中のY×2ローリングだけを行います。`LEGACY_COMBAT`、RPush後FIELD専用待機、FIELD復帰直後の短い移動ではどちらも処理しません。
- 「力を溜めている」を検知した時点で通常攻撃と左移動を止め、最大3.5秒だけ緑床を探します。
- 緑床までの算出移動時間が1.35秒以内なら近距離と判断し、既存の`GREEN_MOVE`／`GREEN_HOLD`へ移ります。強い光の予兆経由の`GREEN_HOLD`だけは緑床が0.6秒連続で消えるまで維持します。
- 緑床が見えても1.35秒を超える遠距離なら、間に合わない床として直ちにZLを解除し、Y回避を7秒間維持します。
- 床を見つけられない間は、保存中の一方向へ右スティックを0.12秒だけ動かして再確認します。通常探索の強度約0.48より少し速い約0.58とし、次周の停止後fresh frameで緑床を判定します。時間だけで左右を交互に切り替えません。
- 「強い光を放つ」を検知するか3.5秒の探索期限に達した場合、ZLを解除し、左移動と視点を止めてYを3秒間送ります。完了後はZLを戻し、次の周期から`FREE_RUN`の視点回転・移動・Aを再開します。古い壁方向の左移動や無期限FIELD待機へは戻りません。
- 同じ通知が画面に残っている間の再発動は防止し、通知消失後の次の予兆から再度有効になります。
- 登録画像は保存済みSwitch No2録画から切り出し、閾値0.78、検知範囲`[840,170,1275,360]`です。

## ターゲット探索と移動

- ターゲットマーカーを優先し、取れない場合は赤／青の敵領域を補助判定に使います。
- mode 5の直接マーカー照合では、左下の手持ちポケモン固定UI（1280×720基準で`x<430, y>=500`）を候補から除外します。UI内の青緑輪郭をロックオンマーカーとして保存せず、右スティック探索を止めません。
- 赤と青が同時に有効候補になった場合は青を優先します。青候補がない場合だけ赤へ戻します。
- 赤／青補助は、開始フラグ4かつ直近1.5秒以内に `BATTLE` / `FIELD_W` / `FIELD_BACK_W` / HARD FIELDのいずれかを確認した場合だけ有効です。コメント・選択肢・暗転では期限を即時破棄します。
- 色は狭いHSV範囲だけでなくBGRの赤／青優勢度、明度、彩度、輪郭内比率、形状を併用します。上部HP・下部手持ち／技UI、暗い青背景、全画面寄りの攻撃発光は候補から除外します。
- 実マーカー／C+／EYEによるロックオン確認がない色候補は、同色・近い位置・近い面積を3回連続確認してから採用します。
- 確定した色候補はPokeConプレビューへ600ms表示します。赤敵は赤枠、青敵は青枠です。
- 左スティックは検出方向へ強度1.0で保持し、短い `press` の反復による減速を避けます。
- マーカー未検知中も最後の左右方向を保存し、同じ向きへ右スティック探索を続けます。時間だけでは左右を反転しません。
- マーカー未検知中の右スティックは0.70秒保持し、0.45秒の再ロック確認を挟んで同じ方向へ戻ります。
- ロックオン未確認で赤／青だけを取れた場合は、その色位置方向へ左スティック強度1.0で移動します。
- 実マーカー／C+／EYEによるロックオン確認中に赤／青が見えた場合は、遠距離では`dir1`（mode 5では20度）・強度1.0を維持します。敵中心が画面下寄り、または輪郭が大きい近距離では20／160度の横移動へ切り替え、敵へ直進し続けず攻撃距離を残します。この場合はZLの解放・再入力も行いません。
- 黄色HP約1/4で再開した区間だけ、実マーカーまたは赤／青補助と画像ロックオンが成立した後の90度接近を無効にします。敵が近い間は通常方向が0度付近なら300度（反対側は240度）の斜め後方へ移動し、ターゲット中心Yが420以上で後退開始、360以下で距離確保とします。境界間では直前状態を保つため、1フレームの位置揺れで方向を往復しません。距離確保後は0～20度（反対側は160～180度）の横移動へ切り替え、A／C+攻撃を継続します。一度ロックオンした後は、マーカーの短い未検知や赤青の色検知だけになっても、従来の55／125度や色位置由来の約60～90度の接近には戻らず、20／160度の距離維持で再捕捉を待ちます。一度もロックオンしていない間だけ、再捕捉に必要な接近を許可します。

## 攻撃

- AはC+画像がなくても安全な戦闘画面で継続しますが、入力しただけでは
  300秒無攻撃時計の「攻撃成功」には数えません。
- `LAST_48`のTESTMODE1で青／赤障害物内を攻撃する区間は、ZL保持中に
  C+／C+_LOWを確認せずA→Bを連続入力します。未確認のA／Bはいずれも
  300秒無攻撃時計の「攻撃成功」には数えません。
- C+またはC+_LOWを確認できた場合はPLUSを先に押し、B/X/Yも技入力として使用します。
- 最終戦固有の4技UIにはC+がありません。Switch No2の実フレームから切り出した「コアパニッシャー」「サウザンアロー」「サウザンウェーブ」「グランドフォース」を`POKEMON_ZA_LAST_BATTLE_MOVE_UI`の4パターン（OR、各閾値0.8）として確認します。
- イベント戦闘開始画面では、4技UIがZLロックオン後まで表示されない場合があります。4技UIは毎周先に確認します。無期限FIELD待機中はFIELDなしが180秒続くまで`last_battle_name.png`を照合せず、180秒到達後だけ名称の連続表示を計測します。名称が5秒連続し、FIELD_W／FIELD_BACK_W／HARD FIELD／Escapeがすべて不在の場合に限ってZLを解放・再保持し、合計0.3秒後に4技UIを再確認します。名称または除外画像の条件が1周でも崩れれば5秒計測を即リセットします。4技UIがなければ盲目Aを送らず直近の青／赤／青戻り／FREE_RUNへ戻し、同じ名称表示中の再ZLを抑止します。名称が0.5秒以上消えた後だけ、次の名称表示を新しい5秒確認として扱います。SELECT後の`RETRY_SELECTION`／`WAIT_RESUME`でローカル`nofiled=0`が残る場合とRPush後FIELD待機も同じ180秒時計を使います。180秒後も名称がなければ敗戦にせずFIELD待機を継続します。
- ただしイベント暗転で残った敗戦ラッチ中は、実SELECT／黒Commentなしと名称画像一致を確認した場合に180秒条件を迂回します。黒背景単独は敗戦確定条件ではないため名称救済を阻止しません。敗戦Aを止めて名称を新たに5秒連続確認し、実SELECT／黒Commentが名称確認中、ZL直後、または固定4技入力中に出れば敗戦処理を優先します。固定4技UIが出た経路では1技以上の正常入力後に古い敗戦ラッチを解除します。UIが出ない経路では誤って残ったラッチを解除し、直近戦闘へ復帰します。
- 4技UIを確認した場合だけ、通常C+分岐を迂回して右視点を停止し、ZLを保持してA→X→B→Yを送ります。PLUSは送りません。各ボタン直前とY入力後に4技UI・実敗戦候補を取り直し、画面が切り替わった時点で残り入力または完了遷移を止めます。
- 固有4技を1つ以上入力した時点で、敗戦後と同じ`RETRY_SELECTION`／`WAIT_RESUME`、開始フラグ0、戦闘停止状態へ移ります。FREE_RUN、予兆、側別時計、ロックオン追跡を破棄しますが、黒背景5秒確認済みを意味する敗戦ラッチ自体は有効にしません。
- 固有4技後は専用FIELD待ちラッチを維持し、同じ4技UIが残っても再攻撃せず、180秒経過後の名称判定にも戻りません。XメニューのB最大20回と厳密な敗戦判定は維持します。`FIELD_W`では既存の上入力を優先し、`FIELD_W`が消えた後のHARD FIELDまたはEscapeでだけ既存の再戦初期化・HP分類・青側開始処理へ進みます。
- 4技UIはHARD FIELD／Escape、緑床、フリーランの強い光処理、TESTMODE1より先に処理します。同じ周回で別のモード遷移は行いません。
- C+画像を確認できないB/X/Yの順番はAへ戻します。これによりBダッシュやYローリングを防ぎつつ攻撃回数を維持します。
- C+を一時的に取れなくても、安全な戦闘画面を確認できる場合はAを継続します。
- コメント、選択肢、暗転中にはAを送りません。
- mode 5では画面端2辺以上の赤い被弾表示を検知すると、緑床を再確認します。緑床への移動中／床上待機中はそちらを優先し、ZL解除やY回避を挟みません。
- 緑床処理が不要な場合だけZLを解除し、Yを6回送ってからロックオンと継続移動を復帰します。同じ赤表示中は再実行せず、赤が消えた後の次回被弾で再度有効になります。
- mode 0～4では従来のRCLICK後35秒の攻撃継続を維持します。C+を取れない通常区間の追加フォールバックもAだけに限定します。

## ポケモンを出せない場合の復旧

- mode 5の開始フラグ3または戦闘中のフラグ4で`FIELD_W`が残った場合、`Lbutton_up`を0.3秒以上の間隔で最大5回送ります。
- 5回後も`FIELD_BACK_W`へ変わらず`FIELD_W`が残る次周期で、左移動、視点探索、ZLを止めてXを1回送ります。
- `POKEMON_ZA_X_MENU_OPEN`を確認できた場合だけBを同一メニュー表示エピソードで最大20回送り、メニューを閉じます。X入力を取りこぼしてメニューを確認できない場合は、戦闘中のB入力へ化けないようBを送りません。
- 白／緑／黒Comment、3_SELECT_TUTORIAL、3_SELECT、4_SELECTを確認している間はX/B復旧を保留します。
- 復旧周期中は攻撃処理へ進まず、上入力回数をリセットして開始フラグ3からポケモン選択をやり直します。mode 0～4には適用しません。
