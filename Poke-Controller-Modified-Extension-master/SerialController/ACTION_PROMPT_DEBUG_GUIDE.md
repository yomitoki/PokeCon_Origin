# A表示の確認とDebug_A_Check

通常はZIPの保存画像から切り出した「Aマーク＋文字」を比較します。
参照は `Template/ZA_Story_PIC/ActionPrompts/catalog.json` が正本です。
「はいる」「でる」「話しかける」「調べる」「のぼる」「拾う」「ふれあう」
「座る」「エレベータ」の9種類を、元画像・切り出し座標・動画参照・SHA付きで収録しています。
画像の比較部分にはマスクを使用し、文字とAマークを残して周囲の背景を除きます。
従来の入口・出口などの指定は対応する文字を確認します。
文字を指定していなかった `DOOR_A` / `OTHER_A_MARKER` は、この9種類のいずれかを確認します。
画像収集の補完設定がONでも、この判定をAだけの判定へ自動置換しません。

## 使い方

1. Commandsを停止してF5 Reloadし、開始設定で `Debug_A_Check` をONにします。既定はOFFです。
2. 同じ処理で通常の「A＋文字」確認が3回不一致になると、Aマークだけで再確認します。
   固定移動後は、最大3秒の待機確認を1回と数えます。待機中の各フレームや候補画像の数は加算しません。
   即時の画像確認は、その呼出し1回で1試行です。
3. Aだけの再確認は、新しい同一フレームで非戦闘FIELDを確認し、会話・選択肢・メニュー・戦闘表示がない場合に行います。
   Aの内側17×17を入口付近の範囲で比較し、一致度0.90以上を必要とします。
4. 一致したら、画面と全参照候補の比較を保存して、その箇所の既存A操作へ進みます。
   保存に失敗した場合は成功扱いにしません。A操作を実行する前の証拠が残ります。

同じStep内でも行や継続処理が違えば別に数えます。
映像がない場合は試行を加算せず、正常一致した箇所の試行数は解除します。
3回目にもAが一致しなければ、従来の待機・復旧処理を続けます。

## 保存先と内容

保存先はPokeConの `SerialController/Debug_A_Check/` です。
Commandsの開始時に保存先を初期化したり、過去の記録を削除したりしません。
最初の保存時に必要な場所だけを作り、以後は固定の `index.html` と `index.jsonl` に追記します。
複数の実行の記録を同じ一覧から参照できます。

各保存項目には次を残します。

- `frame.png`：判定と全候補の比較に使った、元サイズの同一画面。
- `report.html`：一致度が高い順の全候補、判定値・閾値・探索範囲・参照画像・比較部分・マスク・出典。
- `ranking.csv` / `event.json`：全候補の数値、検出位置、手動指定名、参照先の行・関数・処理内容。
- `source_snapshot.py`：保存時のソースとSHA。実行中の行・関数・コード識別情報も別に残します。

読み込めない候補もエラーとして一覧に残します。一致度のない候補は末尾です。
異なる候補が同点の場合は同じ順位にし、並びを固定します。
「一致度」はテンプレート比較値であり、成功確率ではありません。

## 手動で判定を変更する場合

1. `Debug_A_Check/index.html` から該当項目を開き、保存画面と上位候補を見比べます。
2. 「実行箇所と保存時ソース」でStep・関数・行・処理を確認します。
   ディスク上の行と実行時の行がずれたり、候補行が複数あったりする場合は、その旨を表示します。
   保存ソースが実行中のメモリーと同じだったという保証にはしません。
3. 順位表の `manual_target` を使うと、その参照画像を明示できます。
   例：`ZA_ACTION_PROMPT_ENTER_JA` は「A はいる」の参照です。
   `image_check("ZA_ACTION_PROMPT_ENTER_JA")`、または該当する
   `ZA_story_checked_movement_action` / `ZA_story_wait_movement_a` の画像名に指定します。
   元の移動やA操作の内容は、その必要性を別に確認してから変更します。
4. Commandsを停止してF5 Reloadし、変更した箇所を再確認します。

順位が1位というだけで正しい操作だと決めず、保存画面に表示された文字と照合してください。
今回の明るいABSOL_MOVE21入口では、ZIP由来の通常参照が不一致でも、
Debug_A_Checkの3回目にAマークで確認し、修正用の記録を残せることを保存画像で検証しています。
実機での通過は未確認です。

## 別のPokeConへ配布するとき

`ZA_story.zip`、`LocalFunction.zip`、`ZA_Story_PIC.zip` を同じ更新分で揃えてください。
今回の判定は `ActionPromptCheck.py` / `ActionPromptDebug.py` と、既存の
`ImageDetection.py` / `MaskedTemplate.py`、新しい `ActionPrompts` 画像一式を使用します。
OriginとstockではLocalFunctionの配置が異なりますが、それぞれの従来の配置を保ちます。
既存の `Debug_A_Check` 保存フォルダーを配布物で初期化・削除する必要はありません。
