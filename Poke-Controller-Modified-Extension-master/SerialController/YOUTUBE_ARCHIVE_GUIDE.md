# PokeCon YouTube限定公開アーカイブ

Recording タブ上部の「録画動画の保存先」で「YouTubeへアップロード」を選ぶと、通常録画と Commands 監視録画を YouTube の通常動画として逐次アップロードします。ライブ配信は使用しません。PCへ動画を残す場合は「PCへ保存」を選び、保存フォルダと容量監視は「PC保存設定」タブ、チャンネルや分割時間は「YouTubeアップロード設定」タブで設定します。「録画なし」を選ぶと、通常録画とCommands Start時の自動監視録画は開始しません。この3択とRecording設定はInputSetとRecordingセットに保存されます。

## 初回設定

1. Google Cloud でプロジェクトを作成し、YouTube Data API v3 を有効にします。
2. OAuth 同意画面と「デスクトップ アプリ」用 OAuth client を作成し、client JSON をダウンロードします。
3. PokeCon の Recording →「チャンネル認証・既定設定…」→「OAuth JSONを読込して認証…」を開きます。
4. ブラウザーでアップロード先の YouTube アカウントを認証します。
5. 通常はその設定を既定にします。別チャンネルへ保存する InputSet だけ、Recording のチャンネル欄で設定名を選びます。

OAuth の client secret と refresh token は InputSet には入りません。`profiles/<profile>/youtube_channels.json` に、現在の Windows ユーザーだけが復号できる DPAPI 暗号文として保存されます。

InputSetでは直下の`recording`セクションを正本とし、旧形式の`all_tabs.recording`は直下設定がない場合だけ互換読込みします。保存先キー自体がない従来InputSetは、現在開いているInputSetのYouTube／録画なし設定を引き継がず、従来どおり「PCへ保存」として読み込みます。

## Commandsへアップロードする映像

「Commands映像」は InputSet ごとに次の3種類から選べます。選択は次の Commands 録画チャンクから反映され、YouTubeへ送る保存確定動画にも引き継がれます。

- 「画像検知枠＋ログ（既存録画）」: Camera映像へ検知枠を描き、選択中のOutputログを右側へ合成します。
- 「ゲーム映像のみ」: 検知枠やログを合成せず、PokeConへ入力されたゲーム映像だけを保存します。
- 「PokeCon画面全体」: メインのPokeConウィンドウ全体をWindows Graphics Captureで別取得し、縦横比を維持したまま動画へ収めます。ダイアログなど別ウィンドウは対象外です。

アップロード用に3本を同時生成する設定ではありません。選んだ1種類をCommandsの保存動画として作成し、その動画をアップロードするため、不要なローカル容量を増やしません。通常録画の「Output layout」は変更しません。「PokeCon画面全体」を選んだ場合だけ第2のネイティブウィンドウ取得を起動し、ゲーム入力とプレビューの取得経路は切り替えません。

「Commands低品質許容」はInputSet／Recordingセットごとに保存されます。ONでは、音声を入れていない長時間録画などで実表示フレーム数が少なくても、`recording_timing.json`のCommands記録時間とAVIの実映像時間が一致していれば警告付きで結合・アップロードします。OFFでは従来どおり実表示フレーム不足を確認待ちにします。ON/OFFを実行途中で切り替えた場合も設定変更点を結合境界とし、各録画を作成時の設定で判定します。ONでも記録時間情報がない、時間がずれている、AVIが短い場合はアップロードせず、その異常区間だけを保護して後続の正常区間を処理します。AVIを一時的に読めない場合は同じファイルを再試行し、同一性が変わらないまま12回以上かつ5分以上読めない場合だけ、その区間を確認待ちにします。異常区間に古い削除予定が残っていても、前後を1本へ跨いで結合しません。

## 保存と削除

- 公開設定は `unlisted`（限定公開）固定です。URLを知っている第三者は閲覧・再共有できます。
- 複数の PokeCon は同じ永続キューを共有し、同時に複数本を送らず1本ずつ処理します。
- 既定は120分ごとに通常動画へ分割します。容量を小さく抑えたい場合は10～30分を指定できます。12時間以上のライブアーカイブ制約には依存しません。
- YouTubeモードの通常録画は、分割時刻に次の録画へ切り替えて録画を継続しながら、前の区間をバックグラウンドでMP4確定・キュー登録します。InputSet切替中の区間は切替前の保存先・チャンネル・分割設定で完了させ、新設定を混ぜません。
- YouTubeモードのCommands監視録画は、Commands実行中も30秒ごとの内部チャンクを`recording.avi`と、音声がある場合は`recording.wav`として閉じます。この内部チャンクを1本ずつMP4変換・アップロードすることはありません。
- 設定した分割時間（既定120分）に達するたび、Commandsと次の録画を継続したまま、対象のAVI/WAVをバックグラウンドで直接1本のMP4へ結合します。24時間Commandsを実行する場合も、この「結合→キュー登録」を分割時間ごとに繰り返し、Commands停止まで待ちません。
- 結合前に各元チャンクフォルダーの実体（実パス・device・inode）を固定し、結合済みMP4とアップロードジョブが共有永続キューへ確実に保存され、元チャンクの`command_monitor.json`にそのフォルダー実体と期待するJob ID／動画／sessionの関係を保存できた後だけ、結合元のAVI/WAVを削除します。結合またはキュー登録に失敗した場合、元チャンクは削除せず再試行に備えます。Stop時は最後の分割時間未満の端数だけを保存確認後に確定します。
- キュー登録後も、YouTube APIでアップロード先の動画処理完了を確認するまでは、結合済みMP4をPC上に保持します。処理完了後にそのローカル動画・音声を自動削除します。
- 完了後に削除するのは `recording.mp4`、`recording.avi`、WAV、一時分割動画だけです。`youtube_remote.json`、`command_monitor.json`、`steps.jsonl`、JPEG、ログ、ソーススナップショットは残ります。Commandsの結合待ち・キュー登録済みの状態は、各チャンクの`command_monitor.json`が再起動後の復旧ジャーナルになります。
- 削除対象はYouTube処理完了時に永続クリーンアップjournalへ固定し、登録時のsource identityと現在のファイルが一致するものだけを削除します。録画フォルダー自体も固定した実体を同じ親フォルダー内のランダムなtombstone名へ原子的に移し、移動後にもう一度フォルダー実体とキュー／結合済み動画を検証してから削除します。同じパスに後から置かれた別ファイルと、必要なidentity journalのない旧ジョブのファイルは自動削除しません。Windowsが実ファイルを削除できた時点で初めて容量が空きます。ファイル使用中などで削除できない場合は、親フォルダー側の永続sidecarを残して低頻度で再試行し、PokeCon／PCの再起動後も隔離先の同一実体だけを復旧します。部分削除後に元の`command_monitor.json`がなくてもsidecarから再開し、元パスへ後から作られた別録画には触れません。
- アップロード中に PokeCon を閉じても、別プロセスのワーカーが継続します。PC終了や通信断の後は、次回 PokeCon 起動時に永続キューから再開します。
- PokeCon本体とは別にアップロードworkerが動くため、アップロード処理の更新を反映する時は、すべてのPokeConと`YouTubeUploadWorker.py`を停止してからまとめて起動し直します。PokeCon本体だけの再起動では、旧workerが共有ロックを保持したまま継続する場合があります。キュー、再試行時刻、日次quota停止は永続化されるため、再起動しても失われず、quota自体が早く解除されるわけではありません。
- 通信速度が録画速度より遅い場合やYouTube側が処理中の場合、安全のため未送信動画は削除しないので、その分だけ一時容量は増えます。
- Recordingの「キュー状況…」には、Job ID、録画開始～終了時刻、動画長、登録／更新時刻、試行回数、YouTube ID、次回再試行時刻を表示します。動画を開かず`command_monitor.json`とキューJSONだけを読み、終了時刻が未記録なら開始時刻と動画長から補います。
- キュー一覧、認証情報、チャンネル設定、再認証後のキュー再開は画面外で読み書きします。大きなキューや低速ディスクでもCamera表示とCommands監視を長時間停止させません。

## 中断・再開と安全状態

- 通常録画は、録画開始時にアップロードintentと固定したチャンネルを永続キューへ記録し、録画のfinalize manifestへそのジョブパスを紐付けます。録画後の異常終了があっても、回復workerは同じintentでMP4確定とアップロードを続行します。Commands監視録画は30秒ごとの個別MP4確定を行わず、`command_monitor.json`を復旧ジャーナルとして、未結合区間とキュー登録の関係を再起動後も引き継ぎます。
- 各partのresumable session URL、送信済みbyte数、元ファイル／partのsource identity、YouTubeが返した`video_id`をジョブJSONへ原子的に保存します。`video_id`はYouTube処理状態を問い合わせる前に保存するため、その直後に停止しても新規動画を作らず、既存IDの処理確認から再開します。
- 各PUTの前後にsource identityを再確認します。送信途中の元動画やpartが差し替えられた場合、同じsessionへ異なるデータを送らず、ローカルとリモートの参照を残して停止します。
- 録画を「保存しない」とした場合は、ワーカーと共有する状態ロック下で未送信intentを先に`cancelled`へ保存してからローカルデータを破棄します。リモート送信の開始後などキャンセルを安全に確定できない場合は、データを削除せずMP4確定・保持を優先します。
- 破損JSON、未知の状態、再起動、複数PokeCon、キャンセルが競合しても、1ジョブごとのOSロックで直列化します。既存ジョブを上書きせず、不正なジョブはバックアップを残して隔離します。新しいJob IDはWindowsの大文字・小文字を正規化した動画／session絶対パスから作り、従来Job IDも互換読込みします。両方式で同じ録画を指す複数ジョブや、ファイル名・payload・動画／sessionが一致しないジョブは、API呼出しとローカル削除の前に確認待ち／隔離へ止めます。

次の状態は、重複投稿や誤削除を防ぐため自動workerの対象から外れます。キューJSONのパス、エラー、session URL、`video_id`、ローカルパスは手動確認のため保持されます。

- `authentication_required`: OAuth認証が無効です。Recording設定から同じprofileを再認証すると、ローカル動画または既存`video_id`が残るジョブはそこから再開できます。
- `upload_attention_required`: 通常の一時エラーが30回失敗したか、再試行しても直らないHTTP 400を1回検出したか、同じ録画を指す複数の有効なキュージョブを検出しました。設定、元動画、APIエラー／重複ジョブを確認するまで自動再試行しません。
- `quota_waiting`: YouTubeの`Video Uploads per day`上限に達しています。レスポンスのquota window開始から24時間＋5分までキュー全体を止め、他の動画にも同じ失敗要求を繰り返しません。分単位など日次アップロード以外のHTTP 429は通常の短い再試行として扱います。
- `remote_verification_required`: 保存済み`video_id`の可視性／処理状態を確定できません。IDを破棄して再投稿せず、YouTube Studioで既存動画を確認します。
- `remote_processing_failed`: YouTube側が動画処理の失敗を明示しました。`video_id`とローカルデータを保持し、利用者の判断を待ちます。
- `source_verification_required`: 送信元として固定したファイル／partの同一性を確認できないか、差し替えを検出しました。追加PUTを行わず、既存のsessionとローカルデータを保持します。
- `cleanup_attention_required`: YouTube処理完了後もローカル対象を30回削除できませんでした。ファイル使用中、権限、journalの残存対象を確認します。
- `invalid_job`: キューJSONの破損または未知の状態です。元JSONはバックアップされ、新しいジョブで上書きされません。
- `cancelled`: リモート送信前に意図的に取り消したジョブです。自動再開しません。

`waiting_media`はAPIエラーではなく、ローカルMP4の確定・復旧待ちです。この状態へ移った時点で過去試行のHTTP 400／429エラーは現在エラー欄から外しますが、本文と元の発生時刻を過去エラーとして退避し、quota時刻などの監査情報とともにキュー画面へ分離表示します。

## Commands と DevStudio

InputSet で「共通3関数の全呼び出し元を索引化」を ON にすると、次の共通関数だけを選択トレースします。

- `ZA_story_Template_battle_before_renda_route`
- `ZA_story_Template_battle_function_renda_route`
- `ZA_story_Template_battle_after_renda_route`

実行時スタックから呼び出し元を取得するため、`_4_story_shiro_35`～`37`に限定されません。同じ共通関数を使う全 Step 関数が `common_function_index.json` へ記録されます。OFF の InputSet では、この追加トレースを有効にしません。

DevStudio の Commands録画タブでは「共通関数の呼び出し元…」から、グループ → 共通関数 → 呼び出し元 → 発生時刻を選べます。「YouTubeでこの時刻を開く」は、長時間録画が複数動画になった場合も該当パートの相対時刻へ変換します。

YouTube動画の説明欄へ書き出すタイムスタンプは、`steps.jsonl`に記録されたStep遷移だけです。Step内で呼ばれた共通関数やその他の関数は説明欄へ出さず、`common_function_index.json`とDevStudioのローカル索引にだけ保持します。同じStepの連続サンプルは1件へまとめ、別Stepを挟んで再び入った場合は新しいStep遷移として記載します。

## API上の注意

- YouTube Data API のアップロードには API クォータが必要です。短いチャンクを個別送信しないのは、この消費を抑えるためでもあります。
- 動画説明へStep経路を載せる前に、YouTubeが拒否する`<`／`>`と制御文字を安全な文字へ置き換え、UTF-8で5,000 byte以内に収めます。同じ内容のHTTP 400を連続再送しないため、決定的な400は最初の1回で確認待ちにします。旧`invalidDescription`ジョブだけはこの補正後に1回再開できます。
- キューの`authentication_required`へ`invalid_grant`が記録された場合は、Google側の認証が無効になっています。Recording →「チャンネル認証・既定設定…」から対象profileを再認証してください。
- 新規・未監査 API プロジェクトでは、YouTube側の制限によりアップロード動画が private 固定になる場合があります。限定公開で運用するには Google の監査が必要になることがあります。
- 動画説明はサイズ制限があるため、Step遷移の時刻だけを載せます。関数時刻を含む完全な履歴はローカル索引が正本です。
- Codexへ解析を依頼する場合は、録画フォルダの `command_monitor.json`、`steps.jsonl`、`common_function_index.json`、JPEG、ソーススナップショットを渡すのが確実です。`youtube_remote.json` には時刻付きURLの解決情報があります。
