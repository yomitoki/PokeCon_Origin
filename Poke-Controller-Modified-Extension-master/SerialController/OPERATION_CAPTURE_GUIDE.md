# 操作記録からCommandsを作る

この機能は、通常の録画とは別の作業用記録です。

- 通常録画: `Recording` タブ
- 操作からCommandsを作る記録: `操作記録→Commands` タブ

設定、開始・停止、保存フォルダ、保存データ、録画処理は分離されています。保存先が空欄の場合は`SerialController/OperationSessions`を使用し、通常録画の録画方式や保存先は変更しません。

## この順で操作します

1. Camera、Serial、PCゲームパッドを接続します。
2. `操作記録→Commands` タブを開き、保存フォルダと入力方法を確認します。
3. `物理ボタン割り当て画面...`を開きます。一覧先頭の`入力確認（変更なし）`を選ぶと、割り当てを変えずに実機ボタンの点灯と`axis:4+`などの検出番号を確認できます。変更時は入力を1回検出し、Switch側の登録先を選んで上部の`検出した入力を選択先へ登録`を押すか、登録先を選んで`次に押す入力を割り当て`を押してから物理ボタンを1回押します。最後に保存します。黄色は選択中、橙色は変更待ち、緑は実際に押下中、水色は選択＋押下を示します。A/Bの物理位置が逆のゲームパッドもここで入れ替えられます。
4. `● 開始`を押します。PCゲームパッド入力と1280x720の元映像を同じ時刻で記録します。
5. 一回で終わらない場合は`一時停止`を押します。停止位置の画像が保存されます。
6. `画像確認して再開`で停止画像を確認し、同じセッションの次区間として続けます。停止していた時間はCommands用の時間に含まれません。
7. 最後に`完了・結合`を押します。全区間を順番に結合し、次のものを残します。
   - 1280x720の元映像
   - ボタン・スティック情報を重ねた確認映像
   - 時刻付き入力記録
   - 停止時画像
8. 一覧で記録を選び、`DevStudioで開く`を押します。

ゲームパッド入力は長押し状態を保持します。たとえばLを押したままAを追加した場合はL＋Aとして記録し、Lだけを離すとAの長押しは継続します。十字キーの上下左右を2つ押した場合は斜め方向として記録します。

## DevStudioでの作業

`操作記録→Commands`タブだけで次の順に進められます。

1. 入力行を選ぶと、その入力時刻へ映像が移動します。
   入力が多い場合は500件ずつページ表示します。検索、前後500件、入力行番号への直接移動が使えるため、1,000～10,000件でも全件を一度に画面描画しません。
2. 必要なら入力と映像の補正秒を調整して保存します。
3. 連続した入力行を選び、次のいずれかへ割り当てます。
   - Stepとして作成
   - 関数として作成（呼出元Stepも指定可能）
   - 直接処理として残す
   - 反映不要
   500件のページ境界をまたぐ場合は、割当欄の`行範囲`へ開始行と終了行を直接入力します。
4. 中間コードの入力対象を選び、`中間コード生成`で割当を中間ファイルへ保存します。
   - `Switchのみ`: 記録したSwitchシリアル入力を忠実に生成します。
   - スティック角度の既定値は`記録角度を保持`です。記録した角度と倒し量を維持します。
   - `8方向へ変換`: 倒し量を維持したまま角度だけを最寄りの45度単位へ変換します。
   - `Switch＋Steam/PS4流用`: A・方向・スティックなどの意味付き入力として生成します。Switchでは精密な角度と倒し量を使用でき、PCキーへ流用するときだけ最寄りの8方向へ変換します。反映先CommandsにはDevStudioのサンプル一覧`Steam_Switch_Game_Input`を追加してください。
   流用対応のPCキーは、サンプルの`game_input_profiles`を編集するか、`set_game_input_mapping()`を呼ぶことで生成後にも変更できます。割当自体は`mappings.json`へ常時保存されるので、閉じても残ります。
5. 最終ソースと反映先クラスを選び、差分を確認します。
6. 未割当が0になったらソースへ反映します。反映前のファイルは日時付き`.bak`として保存されます。

## 映像から画像検知を作る

1. 対象時刻へ映像を移動します。
2. `現在フレームから画像検知`を押します。
3. 画面内で、他の似た場所を含めない小さめの特徴部分をドラッグで囲みます。
4. `保存して画像検知タブで調整`を押します。

元の1280x720座標と切り出し画像が既存の画像検知タブへ渡ります。閾値、グレースケール、類似度出力などは画像検知タブで確認してから保存します。

切り出した画像は最初はSwitch／Steam／PS4で同じものを使用します。流用対応Commandsでは画像の論理名を`game_image_check()`へ渡し、必要になった画像だけ`game_image_profiles`または`set_game_image_mapping()`で機種別の画像検知名へ差し替えられます。Stepや関数側の論理名を書き換える必要はありません。

## 動画判断・デバッグCommands

`動画解析＋デバッグCommands生成`を押すと、各Stepの最後の入力から少し後の元映像を調べます。Step開始付近からの変化が大きく、直後の動きが少なく、模様に特徴がある領域を1件ずつ候補画像として自動保存します。Stepが未割当の場合は、現在表示中の動画位置付近約1分から最大5個のデバッグ専用仮Stepを作ります。この仮Stepは通常の`mappings.json`へ保存せず、最終版には使用しません。

- 表示先は`動画判断・疑似サンプル`タブです。通常の`中間ファイル`とは切り替えて確認でき、`ソースへ反映`には自動で含まれません。
- 候補画像は記録セッション配下の`debug_command/templates`、時刻・範囲・信頼度などは`debug_command/vision`へ保存されます。他の画像ライブラリとは混ざりません。
- 実行可能な編集用コマンドは`debug_command/working_command.py`です。再生成前の編集版は`debug_command/working_history`、生成版は`debug_command/generated_history`へ残ります。
- `中間コード生成`を明示的に押した版は`debug_command/intermediate_history`へ毎回保存され、`前回の中間コードと比較`で直近2版の差分を確認できます。
- `デバッグ編集`で作業版を調整し、`Commandsへ配置`で`Commands/PythonCommands/GeneratedDebug`へ明示的にコピーします。PokeConでCommandsを再読込すると`[DEBUG]`で始まるコマンドとして実行できます。
- デバッグCommandsの生成・配置は最終ソース欄、差分、`ソースへ反映`を変更しません。
- Switch／Steam／PS4の画像パスは初期状態ではすべて同じです。メタデータの`platform_templates`を後から機種別画像へ変更できます。
- 疑似サンプルは、同じクラスにある通常の中間Stepを呼び出し、約0.4秒後に指定画面を検知したら次Stepを返します。検知できない場合は最大5分のサポート待ちへ入り、外部操作または`operation_support_callback`による支援後に同じ画面を再検知して通過します。
- サポート要求、支援後の通過、タイムアウトは`debug_command/logs/vision_support.jsonl`へ時刻付きで記録されます。

自動抽出は「使えそうな場所」の推定であり、正しい画面遷移を保証するものではありません。生成コメントの候補時刻と信頼度を参考に、保存画像、範囲、閾値を実機で確認してください。必要なら従来どおり`現在フレームから画像検知`で候補を置き換えます。

## InputSetへの保存

保存フォルダ、音声記録、PCゲームパッド自動接続、選択したゲームパッドプロファイル、最後に開いたセッションをInputSetへ保存します。プロファイル本体はPokeConプロファイル内の`operation_gamepad_profiles.json`へ保存します。操作セッションの`session.json`には、録画時に選択したプロファイル名と全ボタン割り当てのスナップショットを記録するため、後からPokeCon側の割り当てを変更しても録画時の設定を確認できます。`Commandsを使用しない` InputSetにはこの設定を保存しません。

## 注意

- 通常録画またはCommands監視録画と同時には開始できません。
- SerialとCameraが未接続の場合は開始できません。
- ツール側ドライブまたは保存先ドライブが指定容量を下回ると開始せず、記録中なら自動で一時停止して通知します。
- 操作記録中はCommandsからの送信を待機させ、PCゲームパッド入力を優先します。
- HOME（Guide）はWindows、Steam、Xbox Game Bar、ドライバーが先に取得するとPokeConへ届きません。届く機種では割り当て可能で、届かない場合は別の物理ボタンをSwitch HOMEへ割り当ててください。
- `axis:5-`などのトリガー反対方向はニュートラル確認を妨げません。操作プロファイルで明示的に割り当てた場合だけ操作記録のSwitch入力として使用し、未割り当ての場合は操作・記録へ影響しません。
## Software-Controller input

The on-screen Software-Controller is recorded in the same input timeline as a
PC gamepad. PokeCon records the coalesced state that was actually sent to the
Switch, so long holds and simultaneous buttons remain intact. Each JSONL input
row has a `source` field (`pc_gamepad` or `software_controller`); this also
records the on-screen HOME button even when the PC gamepad Guide button is
reserved by Steam, Xbox Game Bar, or a driver.
