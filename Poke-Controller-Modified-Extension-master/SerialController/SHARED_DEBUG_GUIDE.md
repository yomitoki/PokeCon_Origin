# 複数PokeConでStepデバッグ・関数置換を共有する

同じWindowsユーザーで起動する複数のPokeConから、同じ調整内容を参照できます。
カメラ、Serial、録画などの設定は各InputSetのままで、次の内容だけを共有します。

- Stepデバッグの停止地点と処理ごとの調整案
- 関数置換マッピングと実動作試験ON/OFF
- 置換で使用するPCコントローラー記録

## 設定手順

1. 1台目のPokeConでInputSetを呼び出します。
2. InputSetタブの「複数PokeCon共有（Stepデバッグ・関数置換）」を開きます。
3. 「共有名」に、例として `ZA_story_debug` を入力します。
4. 「このInputSetのデバッグ内容を共有する」をONにします。
5. 2台目のPokeConでも、共有したいInputSetへ同じ共有名を設定してONにします。

初めて使う共有名は、現在のPokeConの内容で新規作成されます。
登録済みの共有名は、共有側の内容を読み込みます。

## 普段の使い方

Stepデバッグや関数置換を編集すると共有側へ自動保存されます。
別のPokeConで変更された内容は、Commands開始時、Stepデバッグ画面または関数置換画面を開く時に再読込します。
すぐ確認したい場合は「共有から再読込」を押してください。

複数画面で同時に編集し、古い画面から上書きしようとした場合は競合を表示します。
通常は「共有から再読込」で最新内容を確認してください。「現在内容を共有へ保存」から意図的に上書きすることもできます。

## 保存場所と安全性

共有ファイルは次に保存されます。

`%LOCALAPPDATA%\PokeConModifiedExtension\shared_debug_library.json`

複数プロセスから同時に保存してもファイルが壊れないよう、排他制御と一時ファイル置換を使用します。
ソースファイルの絶対パスは共有元のものをそのまま適用せず、ソース反映時には現在起動中のPokeConが読み込んだ同名Commandsを優先します。

共有するPokeCon間で対象Commandsの関数構成が異なる場合、処理IDが一致しないことがあります。その場合は実行前検証で中断されるため、同じ版のCommandsを使用してください。
