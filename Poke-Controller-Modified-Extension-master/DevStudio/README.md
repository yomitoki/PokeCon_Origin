# PokeCon Dev Studio

`python PokeConDevStudio.py` で起動できます。PokeCon の **Others** タブからも起動できます。
Windowsでは `StartDevStudio.cmd` または `PokeConDevStudio.pyw` をダブルクリックして直接起動できます。

Pythonファイルの全文検索、関数・クラス検索、タグ付きコードの複数選択・マージ、出力の保存に対応しています。

## 開発機能

- ファイルツリーからの編集・上書き保存／別名保存／新規ファイル
- 行番号、Pythonの簡易キーワード・文字列・コメント色分け
- エディタ内の検索・置換、指定行への移動
- Python構文チェック
- 保存済みPythonファイルの実行、停止、標準出力・エラー表示
- `Ctrl+S` で保存、`F5` で実行

## PokeConコマンド生成

メニューバーの **Commands > New PokeCon Python Command...** から作成します。

- Pythonファイル名、PokeConに表示する名前（`NAME`）、クラス名を指定
- 既存タグをプルダウンから選択、または新規タグを追加
- タグを順に追加すると、`Commands/PythonCommands/tag1/tag2/tag3/` に生成
- `Loop`、`Step`、`One shot` の雛形を選択
- Stepは「章 / 詳細処理」を追加した順に実行するコードを生成

生成後はPokeCon本体で **Commands > Reload Commands** を押します。各生成ファイルには実行対象のクラスを一つだけ置くため、Python Commandの一覧へ二重登録されません。

実行中の変数はPokeCon本体の **Command Watch** タブから監視できます。対象コマンド、出力先、変数名を選び、値が変化した時だけログへ出力します。

実行は選択中のPythonファイルを、そのファイルのフォルダをカレントディレクトリとして起動します。PokeCon本体を実行しているPythonと同じPythonを利用するため、実行対象は内容を確認した上で使用してください。

再利用したい関数またはクラスの直前に、次のようにタグを置きます。

```python
# @pokedev: recording audio utility
def helper():
    pass
```

任意の断片は次の形式で扱えます。

```python
# @pokedev-begin: gui output
# ... code ...
# @pokedev-end
```

マージ結果は雛形です。依存する import、重複する関数名、既存クラスとの接続は保存前に確認してください。

## ソース関数のサンプル登録・一括改名

ソース編集画面の右側にある`Completion`の右隣の`関数登録`タブを使用します。

1. ソースを開き、`関数登録`タブで対象関数を複数選択します。状態テーブルまたは生成Stepに使用される関数は既定で非表示です。必要な場合は`Step関数も表示`で切り替えられます。
2. 必要なら検索置換・先頭追加・末尾追加、または1件の直接指定で登録名を作ります。`完全一致`は既定で有効で、検索文字と関数名全体が同じ関数だけを置換します。類似名も部分置換したい場合だけ無効にしてください。
3. `選択名をソースへ一括反映`で、関数定義と`self.関数名`などの参照をまとめて変更します。
4. `選択をサンプルへ登録`で、関数ごとのサンプルを作成します。ソースのimport文も登録情報へ引き継ぎます。
5. 登録済みの行をダブルクリックするか、`選択サンプルを変更画面で開く`を押すと、サンプル関数タブの変更画面へ移動します。

同名サンプルを更新する場合だけ`同名サンプルは内容を更新`を有効にしてください。無効の場合、既存サンプルを誤って上書きせず処理を中断します。

### 作成済みCommandsの依存グループ登録と登録元への反映

`関数登録`タブの`別の作成済みCommandsを開いて登録`から任意のCommandsを開けます。main関数を選ぶと、`self`経由の呼び出しと`STATE_*_FUNCTION`状態辞書を再帰的に解析し、必要な関数・初期化・importを個別サンプルと1つのサンプルリストへ登録できます。状態辞書だけがある場合は`状態辞書からmainひな形を追加`を使用します。

依存グループには関数ごとの登録元Commandsを保存します。サンプルリストタブでリストを選び、`登録元Commandsとの差分・選択反映`を押すと次の操作ができます。

- 登録元とサンプルを左右差分で確認
- 更新する関数と流用先Commandsだけを複数選択
- サンプル関数全体を選択した登録元へ反映
- 登録元にない関数を追加
- 反映前バックアップから直前の状態へ復元

共有サンプルを複数Commandsで使用していても、未選択のCommandsは変更されません。登録元に未保存の編集がある場合はディスク反映を停止するため、先に保存してください。同じ登録先・同じ関数へ内容の異なるサンプルが割り当てられた場合も競合として停止します。

## 登録画像の一致度をPokeConで確認

DevStudioの画像検知ライブラリへ登録した画像は、PokeCon本体の`CommandsAssist`右隣にある`Image Detection`タブから確認できます。

1. `検索`へ検知名、説明、タグ、または画像ファイル名の一部を入力します。
2. 絞り込まれた`登録画像`と`パターン`をプルダウンから選びます。
3. `1回測定`で現在映像を確認するか、`連続監視`を有効にします。
4. 現在の一致度（例: `0.850000`）、登録閾値、一致／不一致と直近120回のグラフを確認します。

測定はバックグラウンドで行われます。測定間隔は0.2秒以上で設定でき、Commands実行中のコントローラー処理を止めません。検索、選択、パターン、連続監視、測定間隔はInputSetごとに保存されます。DevStudioで登録を変更した場合は`登録を再読込`を押してください。

Cameraタブの`Show Value`を有効にした場合、またはDevStudio登録で`類似度をログ出力`を有効にした場合は、`Image Detection`タブの`出力・タグ設定…`で選んだログにも結果を表示します。出力先を画面に割り当てていない場合は、`反映`時に該当Outputを左右ログへ自動配置します。出力先とタグもInputSetごとに保存されます。

## 登録画像を実行前にチェック

DevStudioのソース編集画面右側にある`画像チェック`タブで、画像検知を一括点検できます。

1. 実際に使用する映像サイズを`基準画面`へ`1280x720`の形式で入力します。
2. `一括チェック`を押します。既定ではエラーと警告だけが表示されます。
3. 問題行を選ぶと、画像サイズ、検知範囲、原因、直し方を確認できます。
4. `画像検知タブで調整`で登録編集画面へ移動します。検知範囲が画像より小さいだけで安全に拡張できる場合は、`範囲を自動修正`も使用できます。

チェック対象は、画像ファイルの欠落・破損、テンプレートより小さい検知範囲、基準画面外の範囲、不正な閾値、透明・低コントラスト画像、空の検知登録、画像検知フォルダーの欠落参照・循環です。自動修正は画像を変形せず、確認後に登録済み検知範囲だけを更新します。

文字画面の色判定などで意図的に単色画像を使用する場合は、警告行を選んで`警告を除外／解除`を押します。除外は選択した画像パターンだけに保存され、通常の問題一覧から隠れます。確認・解除するときは`除外済みも表示`を有効にしてください。画像検知設定を上書き編集しても、この除外設定は保持されます。
# 操作記録→Commands

PokeConの独立した`操作記録→Commands`タブで保存したセッションは、DevStudioの同名タブで開けます。入力記録、1280x720映像、中間コード、最終ソース、差分を一画面で確認し、Step・関数・反映不要の範囲を保存できます。

中間コードは`Switchのみ`と`Switch＋Steam/PS4流用`を選択できます。流用時は`Steam_Switch_Game_Input`サンプルのキー割当を後から変更でき、画像検知も共通論理名を保ったまま機種別画像へ段階的に差し替えられます。

詳しい手順は `SerialController/OPERATION_CAPTURE_GUIDE.md` を参照してください。

入力一覧は500件単位のページ表示です。検索と入力行への直接移動を併用でき、10,000件規模でもTkの一覧へ全件を再描画しません。

# Commands録画の動画・ソース比較

Recordingの`Commands監視録画`で保持した録画は、一覧の`動画・ソース比較`からDevStudioの独立タブへ開けます。

- 動画時刻、状態変数／Step、実行関数、ソース行を同期表示
- `Commandsソース内のみ`をチェックすると、PythonCommandBaseなどの共通基盤を除き、録画対象のCommandsソースで実行された行だけに絞り込み（PokeConの`実行経路`タブで保存したチェック状態も初期値として引継ぎ）
- かんたんStepデバッグの停止地点だけを絞り込み、前後の停止地点へ移動
- 関数名・Step名・ソース名・行番号を検索
- 録画時ソースのスナップショットを表示し、現在のソース編集タブも開く
- PCコントローラーで割り込んだ入力だけを追加イベントとして表示
- 動画フレームから既存の画像検知設定へ連携

タイムラインも500件ずつ表示するため、ループを含む10,000件規模の記録を一度にTreeviewへ投入しません。

## 集中修正

DevStudioの`集中修正`タブ、または`動画・ソース比較`の`集中修正…`から、指定関数だけの修正資料を作成できます。PokeConのCommands監視録画で集中修正モードをONにしておくと、対象関数の呼出し、実行行、returnを動画時刻へ正確に記録します。既存録画でも約0.1秒の実行スタック記録から対象区間を解析できます。

- `self.`付き、`()`付き、カンマ・セミコロン・改行区切りで複数関数を指定できます。
- 同じ関数を複数回通った場合は実行回ごとの動画区間として分けます。
- 区間を選ぶと録画時関数ソース、通過行、動画時刻、実際のStepを表示します。行のダブルクリックで`動画・ソース比較`の同時刻へ移動できます。
- 各区間に本来進むべきStep、状態（未対応／確認中／完了）、問題・期待動作を保存できます。
- `Codex用プロンプトをコピー`は画面上のメモと録画証拠をMarkdownへまとめます。
- `解析資料＋区間動画を出力`は選択区間（未選択なら全区間）のMP4、対象関数ソース、`focus_repair_manifest.json`、`focus_repair_request.md`を録画フォルダの`focus_repair_exports`へ保存します。動画切出しは別スレッド・FFmpeg 1 thread・Windows idle優先度で実行します。

このタブは保存済み録画をオフラインで読み、Camera、Serial入力、実行中Commandsへ接続しません。設定・メモを保存する場合だけ録画フォルダへ`focus_repair_request.json`を書き込みます。

## Commands開発解析（録画後・オフライン）

`動画・ソース比較`上部の`Commands開発解析…`から開きます。この画面は選択したPythonソースをASTとして読むだけで、Commandsをimport・実行せず、Camera・Serial入力・Commands workerにも接続しません。

- `品質チェック`: STATE辞書の未定義関数、重複State、未登録return先、停止判定のない`while True`、到達不能処理、画像検知の未登録を一覧化します。
- `Step遷移`: ソース上の直接return遷移と、録画で実際に通ったStep遷移・回数を並べます。
- `変数履歴`: 録画済み状態変数と、Command Watchで明示的に選択した変数の変更を動画時刻付きで表示します。行のダブルクリックで動画へ移動します。
- `録画画像検知再現`: ソースが使用する登録済み画像検知を、保存動画に対して再実行します。既定600、最大2,000サンプルで、バックグラウンド処理と中止に対応します。結果は録画フォルダーの`command_image_profile.json`へ保存します。
- `回帰ケース＋テスト生成`: 録画時のStep列、遷移、変数変更、ソース記号をJSONとunittestへ保存します。生成テストもCommandsを起動せず、現在ソースの構文・関数記号だけを検査します。

一覧表示は最大500件で、10行ずつイベントループへ返しながら描画します。ソース静的解析は独立プロセス、録画解析・動画デコード・結果JSON保存はGUIスレッド外で行うため、DevStudioの他タブ操作を待たせません。画像再現はさらに、選択した全検知パターンとフレームの組合せを最大12,000照合へ制限し、多数選択時はフレーム数を自動で短縮します。

`CommandsAssist`のかんたんStepは、指定したState/関数の境界で実行中Commandsを止め、次のStateへ進めたり処理を置換したりする実行時デバッグです。一方、条件付きブレークポイントは任意の変数式や画像一致度を実行中に評価して停止する仕組みになります。常時評価とpause所有権の競合が必要になるため、今回のオフライン開発解析には含めていません。

## 過去のCommands実行とStep単位で比較

`動画・ソース比較`上部の`過去実行と比較…`では、以前より先へ進めた録画を基準、今回の失敗録画を今回として選択します。連続する同一Stepだけを1通過へまとめ、別Stepを挟んで戻った同一Stepは2回目、3回目として保持します。表示は`一致`、`今回は未到達`、`今回だけ（再試行候補）`、`Step不一致`に分かれます。

差分行を選ぶと、両方のStep開始画面、画面差分、記録時関数の差分、基準録画と現在の実ソースの差分を表示します。新規録画はStepが変わった瞬間のCamera生画像を`step_frames/*.jpg`へ非同期保存するため、録画出力の画像検知枠・ログパネルを含みません。旧録画にStep画像がない場合はMP4/AVIの該当時刻へフォールバックし、検知枠を含む可能性を画面に明示します。

`基準録画の関数へ戻す…`は、選択した同名関数だけを現在の実ソースへ置換します。変更前にPython構文を検証し、実ソース隣の`.pokecon-command-backups`へ変更前ファイルとJSON記録を保存してから原子的に置換します。確認後に実ソースが変更されていた場合、別関数名、欠落関数、非Pythonファイルの場合は復元を中止します。
