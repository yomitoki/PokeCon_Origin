# 多言語版の補足チェック・画像収集モード

本PokeConの **Commands → Start → Step実行設定** に、今回の実行だけに適用する2項目を追加した。どちらも開始画面を開くたびに **OFF**。前回設定・お気に入り・InputSetへ保存しない。従来PokeConのコマンド側開始画面には項目を追加していない。

| 項目 | ON時の動作 |
| --- | --- |
| 補足画像でのチェック有効モード | 操作表示はAマーク、対象メニューは選択位置・枠・カーソル、敗北後の再戦は選択画面の順番・行数と再開直後のHPを使う。アブソル／最終戦名は戦闘HUD・HP表示で代用する。対象外の判定は従来どおり。 |
| 一致時の画像取得 | 判定した同じ入力フレームの全画面と日本語版の検知範囲を保存する。**メニューの補足一致でも保存する。Aマークで判定できた箇所・再戦関連・代用できたボス名は保存しない。** |

「ゲーム言語」は保存資料の識別用の自由記入欄。ゲームの言語やテンプレートを自動変更する設定ではない。「この設定で開始」「Commands既定で開始」のどちらも、この画面で明示的に選んだ2項目を今回の実行へ適用する。キャンセルでは適用しない。

| `ZA_STORY_COMMON_ZA_RESEARCH_A` | A 調べる |

対象名と既存の参照画像名の両方を確認する。A図柄は既存の `doorA.png` と、暗い「調べる」画像のA部分 `(6,0)-(21,14)` の2種類を使う。ともに15×14px、閾値0.90。日本語の動詞部分は比較に使わない。

探索範囲は、各日本語チェックの既存範囲と、画面中央 `(200,120)-(1080,620)` が重なる部分。画面下部のメニュー説明にあるAは対象外。1280×720の入力を対象とし、別解像度では補足Aの判定を成立させない。既存の除外領域も維持する。

このモードではA図柄の存在を確認する。**「入る・出る・話す」の意味、目的の入口、入場や移動の完了を区別する判定ではない。** 保存済み「話しかける」画面も入口用のA探索で一致することを確認している。

既存の画像チェックが呼ばれた時だけ適用する。会話送りなどのA入力へ新しいチェックを追加せず、探索のため移動とAを繰り返す処理へ新しいゲームリセット条件も追加しない。14番・19番の最大3秒の待機と復帰先、19番の入場直後の退出入力は既存のまま。

補足モードONの場合だけ、次の登録を文字によらない判定へ置き換える。通常モードの動作は維持する。

| 対象 | 補足モードで確認するもの |
| --- | --- |
| Xメニューの通常先頭項目 | 6項目の枠、1番目の白い選択帯、緑のカーソル |
| Xメニューの技変更項目 | 6項目の枠、3番目の白い選択帯、緑のカーソル |
| 「進化する」があるXメニュー | 7項目の枠と1番目の選択帯・カーソル |
| 技入れ替え画面 | 白い上部枠と、既存の非文字カーソルが技一覧／X・Y・A・Bのいずれか1か所にあること |

**進化を済ませてから技変更へ進む既存の順序が前提。** 進化可能な状態のまま技変更の途中から開始すると、項目位置が変わる場合がある。通常6項目と進化可能時7項目を取り違えて技変更を確定しないよう、項目数も確認する。この注意を本PokeConの開始画面にも記載した。

BOXの黒い選択肢は今回の対象外。枠のみの試案は全保存画像の照合でフィールド等3枚に誤一致したため採用せず、従来の画像判定・画像収集を維持する。

道具の種類と「冷凍ビーム」の技名判定は別途確認が必要なため、今回の位置判定へ置き換えていない。日本語画像が一致しなくても、上記の補足判定が一致したメニュー画面は画像取得モードで保存する。日本語側が不一致の場合でも `full.png` と `japanese_roi.png` は保存し、実際には一致していない `japanese_match.png` は作らない。

## 敗北後の再戦（2026-10-24追加）

補足モードでは、日本語の「再挑戦」「HPひきつぎ」を読まず、黒い背景が5秒継続した後に、2／3／4項目の選択枠と現在の選択位置を確認する。黒コメントのページ数と選択画面の順番は区別し、説明ページを挟んでも1つ目・2つ目の選択画面として扱う。直前と新しいフレームの行数・選択位置・枠・質問の描画状態が安定してから入力する。

| 試す手順 | 1つ目の選択画面（HP選択がある場合） | 2つ目の選択画面（表示される場合） |
| --- | --- | --- |
| 引き継ぎ候補 | 上から2番目 | 上から1番目 |
| 満タン候補 | 上から1番目 | 上から2番目 |

HP選択がない通常2項目／最終戦3項目の画面では、1番目の再挑戦を選ぶ。これらは現行日本語版の配置を基にした候補で、候補名だけで引き継ぎ成功とは判定しない。

未学習の間は2手順を交互に試す。再戦後は攻撃を再開する前に相手のHPバーを確認する。**75%固定ではなく、一気に50%や25%へ減って再開した場合も引き継ぎ成功として、そのときの手順を学習する。** 成功した手順は同じCommands実行の以後の戦闘でも保持する。満タンで再開したことを確認したら学習を解除し、反対の候補から交互実施へ戻る。次のCommands開始時には学習を持ち越さない。

測定は画面上部のボスHPバーを対象とし、緑・黄・赤を扱う。0.5秒以上安定した表示で、バー幅90%以下を減少、95%以上を満タンとして扱う。間の値や読み取れない場合は確定しない。戦闘表示が戻ってから2秒以内に確定できなければ未判定で戦闘を再開し、その後の攻撃で減ったHPを学習しない。ロード中も攻撃処理へ渡さず、HELPだけを送り、戦闘表示を待つ。

同じ画面へのAは0.8秒以上空けて最大3回。質問が描画途中、選択枠が不完全、想定外の行数などでは行を推測して入力しない。学習不能でも勝手なゲームリセットは追加しない。

再戦関連の文字画像8種類と、この再戦確認中の画面は画像取得モードから除外する。既存テンプレート・過去の保存資料・録画は削除しない。

## アブソル・最終戦名の代用（2026-10-24追加）

元の名前チェックは進行・復帰に使われるため、チェックそのものは削除せず、**補足モードだけ確認根拠を置き換えた**。固有名を識別する必要はなく、対象Stepで戦闘中と分かればよい、というユーザーの追加指定に対応する。

- アブソル：既存 `FIELD_W` または `FIELD_BACK_W`、既存の文字を含まない `BATTLE` または逃走アイコン、上部のボスHPバーを同じフレームで確認する。FIELD＋BATTLEはポケモンを出した通常移動中にも一致したため、その2つだけでは確定せずボスHPも必要とする。アブソル自身の名前・Lv.の文字は、この代用に使わない。
- 最終戦の通常時：同じFIELD＋戦闘アイコン＋ボスHPを使う。
- 最終戦でFIELDがない時：画面上部のHPバーを確認する。最終戦フラグがある場合だけ適用し、固定位置・細い帯の形・緑／黄／赤の表示を使う。特定のHP割合との一致は要求しない。
- 元の5秒連続確認、ZL復帰、選択肢・コメント優先、同じ画面への再ZL抑止は維持する。HPもFIELDも消えるカットシーンでは、この代用だけで復帰を成立させない。

対象は `POKEMON_ZA_MEGA_ABSOL_BATTLE_NAME` と `POKEMON_ZA_LAST_BATTLE_NAME` の2登録だけ。対象名と元PNG名の両方を照合する。通常モードは日本語の名前判定を維持する。画像取得時も代用が一致したボス名画像は省き、代用できず日本語だけが一致した場合は確認資料として保存する。

## 保存内容

保存先は本PokeConの `SerialController/Captures/Multilingual/<実行日時とCommands名>/`。各サンプルに次を保存する。

- `full.png`: 判定フレーム全体。別の時点で撮り直さず、画素・解像度を維持する。
- `japanese_roi.png`: 日本語版で設定している検知範囲。
- `japanese_match.png`: 日本語参照画像が実際に一致した部分。
- `metadata.json`: 対象名、Step状態、呼出関数・行、参照画像、範囲、一致度・閾値、日本語／補足の結果、記録用言語。

実行フォルダーには一覧の `manifest.jsonl` と保存件数・上限等の `session.json` も作る。画像は登録テンプレート候補として確認できる資料であり、ソースや既存PNGへ自動登録・上書きはしない。GUIからソースへ採用する機能は今回は追加していない。

画像取得だけをONにした場合も、上記A対象ではA図柄を調べ、Aが一致すれば保存を省く。この場合、ゲーム操作の判定は従来の日本語画像のまま。Aが不一致で日本語画像だけが一致した場合は、言語別画像がまだ必要な候補として保存する。両方不一致なら保存しない。元から `doorA.png` だけで判定する既存のA画像チェックも、画像収集から除外する。

同じ対象・画像パターン・Step・呼出位置・一致結果につき、2秒間隔で最大3組、1実行で最大2000組。PNG書込みは別スレッド、待ち行列は最大4組。保存待ちが満杯ならその回の画像保存を省き、件数を記録する。コマンドの画像判定・入力・録画をディスク書込み待ちにしない。

保存対象は登録画像の各パターンの一致時点である。AND条件全体や、10／18番の追加確認などが最終成立したことまでは意味しない。メタデータの `scope` にもこの区別を記録する。
