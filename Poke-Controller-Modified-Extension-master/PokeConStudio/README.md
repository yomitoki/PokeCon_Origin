# PokeConStudio

PokeConStudio は、PokeCon のソース編集、画像検知の確認、実行位置の検討を一つの画面で行うための操作アシストツールです。

画面左側にソース一覧とエディタ、右上に画像検知リスト、右下に実行支援を表示します。PokeCon から開いた場合は、PokeCon が取得している Fresh Frame と既存の Commands 実行支援を共有します。

画面上部の `表示` チェックでは、ソース一覧、ソース編集、画像検知、実行支援を個別に表示・非表示できます。表示状態は名前付き設定へ保存されます。ソース一覧、編集中ソース、画像検知一覧はファイル名だけを表示しますが、読込・保存・比較には内部で絶対パスを保持します。同名ファイルを登録している場合も別ファイルとして扱われます。

## 起動方法

### PokeCon の Other タブから開く

1. 通常どおり PokeCon を起動します。
2. `Other` タブ上部の `Open PokeConStudio` を押します。

既に PokeConStudio が開いている場合は、新しいウィンドウを増やさず既存ウィンドウを前面へ戻します。この起動方法では、現在の PokeCon Camera の Fresh Frame を画像検知に利用できます。

### BATファイルから開く

リポジトリ直下の `PokeConStudio.bat` をダブルクリックします。

このBATはエディタだけを別に起動するものではありません。通常のPokeConランタイム選択を経てPokeCon本体を起動し、初期化後にPokeConStudioを自動表示します。そのため、Otherタブから開いた場合と同じく、ライブ画像とPokeCon実機用の支援ボタンを利用できます。

コマンドプロンプトからは、ランタイムも指定できます。

```bat
PokeConStudio.bat
PokeConStudio.bat -Runtime last
PokeConStudio.bat -Runtime 314
```

`last` は前回選択したPythonを使います。

### 単独起動について

開発・診断用途では、PokeConStudioだけを起動することもできます。

```bat
.venv314\Scripts\python.exe PokeConStudio\PokeConStudio.py .
```

単独起動では、入力欄に `0`、動画ファイル、静止画像ファイルを指定して画像検知できます。ただし、PokeCon本体のFresh Frame、Commandsの開始・終了Step設定、Stepデバッグ、Commands再読込には接続されません。通常はOtherタブまたは `PokeConStudio.bat` を使用してください。

## 名前付き設定と複数パス

画面上部の `設定` プルダウンで、作業単位の設定を切り替えます。最後に選んだ設定は次回起動時に復元されます。

`新規 / 複製…` または `設定を変更…` では、次の項目をそれぞれ複数登録できます。

- ソースファイル
- ソースフォルダ
- 画像フォルダ
- その他Includeフォルダ

ソースファイルとソースフォルダは左側のソース一覧に使われます。画像フォルダは右上の検知候補に使われます。その他Includeフォルダは、通常Python実行時のモジュール検索先と、相対画像パスの解決候補に使われます。

同じ絶対パスは重複登録されません。存在しなくなったパスは設定から自動削除されず、再接続・再作成したときに再利用できます。現在存在しないパスは、ソース・画像の読込時には無視されます。

`現在状態を保存` は、現在開いているソースと、単独起動時の画像入力を選択中の設定へ保存します。パス一覧の変更は、設定ダイアログの `保存` で保存されます。

最後に読み込んだ操作記録と Commands 録画、および各パネルの表示状態も設定ごとに復元されます。

設定は次のファイルに保存されます。

```text
%LOCALAPPDATA%\PokeConModifiedExtension\pokecon_studio_profiles.json
```

## ソース編集

左上の検索欄は、登録されたソースの表示を絞り込みます。ソースを選ぶとエディタへ読み込まれます。

- `Ctrl+S` または `保存` で保存します。
- 構文エラーがある場合は、確認後に保存するか中止できます。
- 保存前には、元ファイルと同じフォルダの `.pokecon-studio-backups` にバックアップを作成します。
- `ディスクから再読込` は未保存内容を破棄して、保存済みファイルを読み直します。

画像検知の自動挿入を含め、エディタ上の変更は自動保存されません。内容を確認してから保存してください。複数クラス、動的に生成する検知設定、独自ヘルパーを含むソースでは、特に挿入位置と差分を確認してください。

## 画像検知リスト

### 基本操作

1. `初期化 / 再読込` を押します。
2. 右下の状態表示が読込完了になるまで待ちます。
3. `開始` を押します。
4. 必要に応じて `一時停止`、`再開`、`終了` を使います。

設定を切り替えたときも画像一覧は初期化されます。`終了` は検知ワーカーへ終了を要求する操作なので、停止表示まで短い時間がかかる場合があります。

PokeConから開いた場合は、Cameraを二重に開かず、PokeConが取得したFresh Frameを共有します。単独起動では、設定の入力欄に次のいずれかを指定します。

- `0` などのカメラ番号
- 動画ファイル
- 静止画像ファイル

検知は一覧を順番に処理し、結果を段階的に更新します。画像数が多いほど、全候補が一巡するまでの時間は長くなります。

### 表示対象と並び順

`ソースで使う画像だけ` がオンの場合、現在の設定に含まれるソースで定義または参照された画像だけを表示します。オフの場合、画像フォルダから見つかったすべての画像も表示します。

このチェックは表示対象に加えて、次に `開始` したときの検知対象も切り替えます。実行中に切り替えた場合は、いったん `終了` してから再度 `開始` すると反映されます。

一覧は次の優先順で並びます。

1. 検知値が高い順
2. 閾値が高い順
3. 検知幅が広い順
4. 検知名順

検知幅の設定値 `0` は未設定ではなく、フレーム全体を検索する指定です。一覧では `全幅` と表示され、並び替えでは最も広い検索範囲として扱われます。緑色は現在の検知値が閾値以上であることを示します。

### 検知内容をソースへ追加する

1. 左側で追加先のソースを開きます。
2. 右上の一覧で一つ以上の検知を選択します。
3. `選択した検知内容を現在ソースへ追加` を押します。
4. エディタ上の追加内容と構文を確認します。
5. `保存` を押します。

追加直後はエディタ上だけの未保存変更です。動作中のPokeCon Commandsへは自動反映されません。保存後、実行中のCommandsを安全に停止してから、右下の `Reload Commands` またはPokeCon側の再読込を使用してください。

ソース解析は安全のためソースを実行せず、Pythonの構文木とリテラル設定を読み取ります。変数計算、外部ファイルからの動的読込、実行時にだけ作られるパスは、自動判定できない場合があります。

## 記録比較と構造化Step編集

画面上部の `記録比較・Step編集…` から、ソースエディタとは独立した比較・構成編集画面を開けます。この画面では、次の三つを同時に確認します。

- 操作記録: `session.json` と `inputs.jsonl`、および `mappings.json` / `step_plan.json` を期待手順として表示
- Commands録画: `command_monitor.json` と `steps.jsonl` を実際に通過したStepとして表示
- 現在ソース: `STATE_*_FUNCTION` のStepと、対応関数内の `operation`、`variable`、`image_check`、関数呼出し、`return` を表示

Step名を主キーとし、同じStepを再訪した場合はその出現順を保持して、未到達、余分な再試行、不一致を表示します。操作記録の時刻とCommands録画の時刻は別々の録画時計なので、秒数同士を直接比較しません。各時刻は、それぞれの録画映像を開く位置としてだけ使用します。

Stepを展開すると、操作記録で整理した処理、`steps.jsonl` に保存されたCommandsの実行行、現在ソースの処理を横に並べます。Commandsの実行行は監視時に得られたサンプリング証跡であり、すべてのコントローラー入力が一行ずつ記録されることを保証するものではありません。そのため、Stepの「一致」はStep訪問順と操作記録・現在ソースの構成比較を表し、実機操作が完全に同一だったことの証明ではありません。必要に応じて `Commands録画詳細` の映像と実行タイムラインも確認してください。

### 現在ソースのStep構成

`現在ソースStep構成` では、`STATE_*_FUNCTION` 辞書のStepを追加、削除、上へ移動、下へ移動できます。

- 既存Stepの関数対応は変更できません。
- 新しいStepは、現在ソースに既に定義されている関数だけを選択できます。
- 関数名、引数、decoratorの変更は、メインのソースエディタで行います。
- 適用しても即時保存はされず、メインエディタ上の未保存変更になります。内容を確認してから `保存` してください。
- 適用前にソースが別途変更されていた場合は、古い構成で上書きせず再読込を求めます。
- 未反映の構成draftがある状態で、再読込、STATE辞書切替、比較画面終了を行う場合は、破棄前に確認します。

### 操作記録Stepからソース関数本体へ反映する

3列比較で操作記録と現在ソースの両方があるStepを選ぶと、`選択Stepの処理をソース関数へ反映…` を使用できます。`操作記録Step編集` で処理の追加、削除、移動、画像条件、関数呼出し、`return` を直した後は、`3列を再読込（未保存Step含む）` で比較表示も更新できます。反映ボタン自体も、保存済みファイルではなく埋め込みStep編集の現在の未保存内容を使用します。

反映前に現在関数と反映後関数を左右表示します。置き換えるのは対応関数の本体だけで、現在ソース側の関数名、引数、戻り値注釈、decorator、STATE辞書、ほかの関数は保持します。未展開の記録入力範囲は、操作記録の入力索引から実際の可読操作へ展開します。索引読込中、比較後のソース変更、別ファイルへの切替、対応関数の行ずれ、未反映のSTATE構成draftがある場合は反映を中止します。

反映先がない「操作記録のみ」のStepから、新しい関数やSTATE対応を暗黙作成することはありません。関数本体の反映対象になるのは、STATE値が正確な `self.method` 形式で、現在の継承順から実装先を一意に証明できる場合だけです。`Other.method`、別名変数、同名候補、外部基底クラスが先に来て実装先が不明な継承は表示を残したまま反映ボタンを無効にします。コマンドクラス自身のoverride、または外部基底より先に確定するローカル実装は反映できます。また、同じ関数を複数のSTATE Stepが共有している場合は、すべてのSTATE辞書を調べて確認画面に対象Stepを表示します。反映後もソースはメインエディタ上の未保存変更、Step編集は従来どおり独立した未保存状態です。必要な内容を確認してから、ソースの `保存` とStep側の `計画を保存` をそれぞれ行ってください。録画証跡、`inputs.jsonl`、`mappings.json`、Commands録画は変更しません。

### 操作記録のStep編集

`操作記録Step編集` では、記録済み入力をStepへ整理し、Stepの追加・削除・移動・分割、操作、関数呼出し、画像条件、式条件、`return` の追加と移動を行えます。`inputs.jsonl` と `mappings.json` は記録証跡として変更しません。編集結果は同じ操作セッションの `step_plan.json` へ保存でき、確認用Python出力も実ソースとは別ファイルに作成します。明示的に上記の差分確認を承認した場合だけ、選択Stepの内容を現在ソースの対応関数本体へ未保存変更として連携できます。

#### 記録映像からimagecheckを作る

1. 操作記録のStepまたは処理を選び、対応する映像フレームを表示します。
2. 必要なら `－0.1秒` / `＋0.1秒` でフレームを合わせます。
3. `現在フレーム → imagecheck…` を押し、検知範囲をドラッグします。
4. 検知名、閾値、グレースケール、保存先の画像フォルダを選びます。保存先表示はフォルダ名だけですが、内部では設定済みの絶対パスを使用します。
5. `保存してimagecheck登録` を押します。選択中のStepへ条件分岐も置く場合は、そのチェックをオンにします。

PNGと切り出し時刻・範囲などの由来情報を保存し、検知定義は現在のソースエディタへ未保存変更として追加します。Step条件も `step_plan.json` へ即時保存せず、操作記録Step編集の未保存draftへ追加します。どちらも内容を確認してから、それぞれの保存ボタンを押してください。元の動画、`inputs.jsonl`、`mappings.json`、Commands録画は変更しません。

切り出し画面を開いた時点の操作記録、ソース、Step選択を登録先として固定し、背後の選択が変わった場合は登録を中止します。既定の検知名には記録セッション識別子を含めます。複数のPokeConStudioが同じ画像フォルダを使う場合も保存処理を排他し、別セッションや手作業で置いた同名PNGを暗黙に上書きしません。上書き確認を待っている間は、ほかのStudioの保存をロックしません。

`操作情報付き映像` にはキー表示などが写り込むため、そこから作成する場合は警告を表示します。通常は `1280x720 元映像` を使用してください。同名PNGを更新する場合は確認を求めます。登録直後の画像検知一覧は、未保存のエディタ内容も使って再構築するため、`ソースで使う画像だけ` がオンでも新しい検知を確認できます。

### Commands録画の詳細

`Commands録画詳細` では、実行タイムライン、録画時ソースのスナップショット、録画映像を連動して確認できます。録画時ソースは比較証跡であり、現在ソースとは別物です。修正はメインのソースエディタで行います。

## 二種類の実行支援

右下には、役割が異なる二種類の操作があります。特に `再開`、`1行進む`、`停止` は、通常Python実行の子プロセスだけを操作し、PokeConで実行中のCommandsは操作しません。

| 種類 | 対象 | 主なボタン | 実機入力 |
| --- | --- | --- | --- |
| 通常Python実行 | エディタ内容の一時スナップショットを別Pythonプロセスで実行 | `カーソルまで実行`、`通常実行`、`選択範囲を実行`、`再開`、`1行進む`、`停止` | PokeCon Commandsとは接続しない |
| PokeCon実機用 | PokeCon本体のCommands、開始・終了位置、Stepデバッグ | `カーソルStepを実行範囲へ…`、`カーソルStepの操作前で停止…`、`Reload Commands` | PokeCon本体の既存機能を使用 |

### 通常Python実行

通常Python実行は、計算、分岐、画像設定生成、補助関数などを素早く確認するための機能です。保存前のエディタ内容を一時ファイルへ書き、現在のPokeConと同じPythonで別プロセスとして実行します。

- `通常実行 (F5)` は先頭から最後まで実行します。
- `カーソルまで実行` も先頭から実行し、実際に実行された行がカーソル行以上へ到達した直前で一時停止します。カーソル行から実行を開始する機能ではありません。
- `選択範囲を実行` は選択文字列をインデント調整し、独立したPythonコードとして実行します。周囲のクラス、関数、変数は自動では引き継ぎません。
- `操作コード直前で一時停止` は、設定に保存された正規表現に一致する呼出し行の直前で停止します。
- `1行進む` は現在のソースファイルの次のPython行イベントまで進みます。import先や別スレッドの内部をStep実行するものではありません。

この実行機能はサンドボックスではありません。モジュール直下のコード、ファイル操作、ネットワーク処理などは実際に実行されます。また、通常Python実行はPokeConのSerial、Camera、現在のCommands状態を安全に引き継ぐ仕組みではありません。コントローラー入力を伴う確認には使用せず、次のPokeCon実機用機能を使ってください。

操作コードの自動判定は関数名の静的な正規表現判定です。別名を付けた呼出し、動的ディスパッチ、独自ラッパーは検出されないことがあります。設定ダイアログの `操作コード判定` でプロジェクト固有のパターンを追加できます。

### PokeCon Commands実機用

この行はOtherタブまたは `PokeConStudio.bat` から統合起動したときだけ表示されます。

- `カーソルStepを実行範囲へ…` は、保存済みソースを再読込してカーソルを含むCommands／State／Stepを特定し、既存の開始位置を保ったまま、そのStepを終了位置として実行設定を開きます。開始位置が未設定なら、そのStepだけを実行する初期値にします。
- `カーソルStepの操作前で停止…` は、同じ解決結果をPokeCon既存のStepデバッグへ登録し、そのStep関数の入口で一時停止する設定を開きます。画面ではカーソルに最も近い操作コードが最初に選ばれます。
- `Reload Commands` は、保存済みソースからCommandsを再読込します。

カーソル位置が複数のCommands／Stateで共有されている場合は、誤った対象を自動選択せず候補選択画面を表示します。未保存の編集がある場合は保存確認を行い、保存しない場合は古いソースの誤実行を防ぐため処理を中止します。また、Commandsの実行中・停止処理中は再読込や対象差替えを行いません。

Stepデバッグの停止単位は既存PokeConの仕様に合わせた「Stateに対応するStep関数の入口」です。任意のPython行へ直接ブレークポイントを置く機能ではありません。通常Python側の `カーソルまで実行` は行単位トレースなので、目的に応じて使い分けてください。

これらは既存のPokeCon Commandsランタイムを操作します。同じ実行支援欄にある通常Python実行とは、プロセスも一時停止状態も別です。通常Python側の `再開` や `停止` を押しても、実行中のPokeCon Commandsは再開・停止しません。

## 推奨する確認手順

1. Otherタブまたは `PokeConStudio.bat` から起動します。
2. 名前付き設定を選び、対象ソースを開きます。
3. 画像検知を初期化し、開始・一時停止・終了を確認します。
4. 必要な検知をソースへ追加し、差分を確認して保存します。
5. 実行中のCommandsを停止します。
6. `Reload Commands` で保存済みソースを再読込します。
7. `カーソルStepを実行範囲へ…` または `カーソルStepの操作前で停止…` で狭い範囲から確認します。
8. Camera入力FPSと表示FPSが通常値を維持していることを実画面で確認します。

FPSやCamera共有に関わる変更は、単体テストだけでは完了扱いにできません。PokeConを完全に再起動し、Stop → F5 Reload → Start後にライブ入力・表示FPSと実際のCommands動作を確認してください。

## 対応Python

PokeConStudioのコアとランナーは、PokeConが対応するPython 3.7互換構文を維持しています。通常利用ではPokeConのランタイムランチャーからPython 3.14互換環境を選ぶことを推奨します。
